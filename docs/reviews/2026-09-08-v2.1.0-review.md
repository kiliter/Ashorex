# v2.1.0 发布前代码审查

基线：`84d2818`（v2.0.0 主线）。审查范围为当前 App 活动心跳、横屏催办、设置固定头、ADR-0041 与 ADR-0042 的完整增量。需求轴和规范轴分别独立审查，以下问题均已修复后运行对应窄测试。

## 规范审查

1. 个人 Bark 原先仅检查 HTTPS，允许普通用户把服务端请求指向任意主机。改为部署者设置完整可信源站列表，保存和发送均校验，禁止重定向；覆盖回环、私网地址、域名后缀、凭据和端口混淆。
2. 催办创建事务原先包含外部 HTTP。改为短事务创建并提交后外发，外发完成后短事务保存结果；创建锁不覆盖网络等待，降级扫描串行并重读状态。并发和回滚测试覆盖每日上限、幂等及失败不发送。

以上两项均属于发布前必须修复的安全或事务边界问题；未发现其他需阻止发布的独立代码异味。

## 需求审查

1. 筛选面板键盘遮挡“应用筛选”，增加键盘避让与低高度紧凑行。
2. 首页固定头的日期面板和多目标可能挤占待办，低高度使用日期弹层和目标摘要，保留管理入口，待办仍独立滚动。
3. 课程库及今日选课横屏键盘下固定区过高，改为紧凑布局；选课空结果也放入列表滚动区。
4. 筛选元数据加载失败未捕获，增加失败提示、重试和防重复打开。

相关 23 项窄测试覆盖键盘边界、固定区位置、300ms 防抖、清空、筛选取消、失败重试及原首页编辑/添加流程。原型和 ADR 同步说明低高度行为，未通过缩小点击区域规避溢出。

## 主审复核与补充修复

- 事务拆分后，全屏本地事件必须仍在短事务内发布，保留 SSE 的 AFTER_COMMIT 语义；补测提交后事件、回滚不通知，以及外发期间父催办被删除的场景。催办相关窄测试共 34 项通过。
- 个人 Bark 配置纳入用户删除预览、显式级联顺序和审计计数，避免删除密钥时缺少可核对的清单。
- 个人/系统 Bark 共用协议适配器但使用独立目的地；API 只依据当前认证身份读写，不返回设备 Key。
- 版本号统一为 2.1.0，发布附件沿用正式签名 Android APK、未签名 iOS IPA、服务端镜像归档。

## 验证边界

本地仅执行修改涉及的窄测试、静态分析、格式化和真实启动健康检查。PR 与标签的全量验证、平台构建由 GitHub CI 完成。真机通知接收、点击唤起和实播仍需人工验收，不以自动化结果代替。
