# 上岸版本路线图

**状态：** 产品方向已确认，但不是冻结需求或实施授权
**日期：** 2026-09-04
**适用版本：** V1.x.x、V2.x.x、V3.x.x

## 1. 文档用途

本文档只记录“上岸”后续版本的产品方向、版本边界和进入开发前的门禁，帮助维护者与编码代理理解长期目标。

本文档不是 Spec、Implementation Plan、Task 清单或验收依据。任何编码代理不得仅根据本文档创建功能代码、空模块、接口、数据库迁移、依赖、基础设施或未来兼容脚手架。

当前版本的实际需求仍以对应版本已经冻结并获人工批准的以下文档为准：

1. 产品与技术设计规范（Spec）。
2. 相关 ADR。
3. Implementation Plan 中的当前 Task。
4. 需求—实现—验收追踪矩阵（Traceability）。

如果路线图与当前冻结文档冲突，当前冻结文档优先。路线图用于提醒未来方向，不能被用来静默改写当前版本。

## 2. 版本总览

| 版本线 | 定位 | 当前允许的工作 | 明确不得提前实施 |
|---|---|---|---|
| V1.x.x | 稳定现有学习监督闭环 | 已冻结需求的实现收尾、Bug 修复、不会改变业务语义的 UI 调整 | 学习端 AI 助教、AI 对话、联网搜索、多集群、主题和背景自定义 |
| V2.x.x | 面向学习者的 AI 助教、学习伙伴升级与报表外部投递 | 当前只允许整理和评审 V2 Spec、ADR、Plan、Traceability | 未冻结前不得实现 AI Tab、会话、工具调用、AI 业务写入、报表投递或新立绘系统 |
| V3.x.x | 全 App 体验、性能、部署、媒体与资料阅读能力升级 | 当前只允许记录方向、指标和待决策问题 | 不得在 V1/V2 中提前引入集群基础设施、双数据库、微服务、主题脚手架、课程仅音频播放、画中画或 PDF 阅读能力 |

除非维护者明确宣布切换活动版本，并完成第 6 节的版本门禁，否则默认活动开发线为 V1.x.x。

## 3. V1.x.x：稳定维护线

### 3.1 固定边界

V1.x.x 固定当前已经冻结的全部需求、核心学习闭环、状态机、业务规则和服务端真相边界，不再增加新的产品主能力。

V1 中已经存在的后台课程内容生产能力继续保留，包括：

- 从 Emby 音频流调用 OpenAI-compatible ASR 生成课时全文。
- 使用 LLM 生成 Markdown 摘要。
- 生成必须由管理员审核发布的题目草稿。

因此，“V2 做 AI”特指新增面向学习者的 AI 助教、对话、搜索和学习伙伴交互，不表示删除、迁移或推迟 V1 已冻结的后台内容生成能力。

### 3.2 允许的变更

- 有明确复现条件、预期行为和回归测试的 Bug 修复。
- 不改变状态机、API 语义、数据归属、可信进度或欠债规则的 UI 布局、间距、文案、可访问性和交互反馈调整。
- 为恢复冻结需求正确行为所必需的最小代码与测试修改。

### 3.3 不允许的变更

- 借 Bug 修复或 UI 调整增加新的业务流程、入口、状态或自动化行为。
- 改变计划、欠债、可信观看、日终结果、答题和报表的业务真相。
- 增加 Flutter AI 入口、AI Chat、MCP、联网搜索或 AI 业务写操作。
- 为 V2/V3 提前创建空接口、空模块、数据库字段、依赖、配置或部署文件。

UI 调整如果需要改变 API、数据库、状态机或用户完成任务的规则，就不再是 V1 UI 调整，必须进入范围变更流程。

### 3.4 V1 学习伙伴基线

V1 已完成学习伙伴「毛线团团」初版。后续维护必须复用现有实现与素材：

- 精灵表：`apps/ios/assets/pets/maoxian-tuantuan/spritesheet.webp`。
- 素材清单：`apps/ios/assets/pets/maoxian-tuantuan/pet.json`。
- 解码组件：`apps/ios/lib/features/companion/presentation/pet_sprite.dart`。
- 悬浮与动作状态：`apps/ios/lib/features/companion/presentation/study_companion_overlay.dart`。

现有精灵表包含 9 个标准状态和 16 个朝向，共 25 个可点名动作；App 目前只接入其中一部分。V1 不得因为素材已经存在就顺手接入未获产品确认的动作，也不得把本地宠物改成 AI 入口。

## 4. V2.x.x：AI 助教与学习伙伴升级

### 4.1 版本目标

V2 在完整保留 V1 学习监督主逻辑和可信数据边界的基础上，增加面向学习者的 AI 助教，让学习伙伴成为可选的上下文交互入口，并支持把确定性日报、周报投递到用户配置的外部消息接收平台。

V2 的产品设计参考快照为：

```text
docs/prototypes/shangan-ai-tutor-v2.html
```

参考文件 SHA-256：

```text
5e9a1e915870aee05181e2fa22ac3a4d692f366967e1092f4e5c3d23bb37798e
```

该 HTML 是 V2 方向性产品原型，不是冻结需求。原型中的示例数据、人物名称、解锁条件、本机存储方案、主动打扰频率、按钮写入行为和具体视觉尺寸，都必须在 V2 Spec 中重新确认，不能直接照搬为实现要求。

准备冻结 V2 Spec 或开始任何 V2 原型相关设计工作前，编码代理必须先询问维护者“V2 原型是否有更新”。如果有更新，应替换仓库内快照并同步 SHA-256；如果文件缺失或校验值不一致，不得凭记忆补全原型，应先请求维护者提供或确认新的设计基线。

### 4.2 候选产品主线

以下能力来自当前原型，只作为 V2 Spec 的候选输入：

- 在现有四个 Tab 基础上增加独立的“助教”入口，形成完整聊天页面。
- 会话的新建、搜索、切换、自动命名、重命名、删除和清空。
- 五类主要问答：学习计划助手、学习进度问答、知识问答与搜索、课程视频推荐、本节课问答。
- 回答优先使用上岸已有课程、课时、考试目标、计划、欠债和可信学习数据，并明确展示依据。
- 课程材料不足时是否允许联网补充，以及来源标题、域名和引用展示方式。
- 从回答中的课程依据或推荐结果打开对应课时；课程依据只定位到课时，不默认定位到具体播放秒数。
- 学习伙伴在首页、播放器等页面提供快捷提问或上下文问答，并可进入完整助教会话。
- 助教回答方式、课程依据、联网补充、会话命名、学习伙伴显示和停靠等设置。

### 4.3 报表外部投递（已确认方向）

V2 增加由客户端管理、服务端执行的报表外部投递能力。这里的“推送”是服务端向第三方消息接收平台发送消息，不是 APNs、FCM 或 App 本地通知。

已确认的产品边界：

- 客户端提供报表投递设置，用户可以分别启用或关闭日报、周报投递。
- 日报在用户 IANA 时区的日终结算和日报生成成功后发送；周报在对应周结束并完成周报聚合后发送。
- 投递内容来自 V1 的确定性日报、周报和晚间审判数据，不由 AI 重新编造学习事实。
- 客户端不直接调用第三方平台；服务端负责保存配置、渲染消息、调用平台、重试和记录结果。
- 服务端使用明确的报表投递提供商端口隔离第三方协议，平台适配器只负责协议转换，不读取或改写计划、欠债、可信进度和报表事实。
- V2 首个且唯一获准实现的平台是 Server酱。抽象边界只为隔离 Server酱协议并允许后续按独立需求增加适配器，不得提前实现其他平台、通用工作流引擎或空适配器。
- Server酱 SendKey 等凭据属于敏感信息，只能由受保护接口提交并保存在服务端；客户端不持久化、不回显明文，日志、错误和普通业务 API 不得泄露。
- 投递失败不能回滚日终结算、阻止报表生成或改变学习数据；失败应保留安全的投递状态，并按获批策略独立重试。
- 同一用户、报表类型、统计周期和接收平台的成功投递必须幂等，调度器重复执行不能重复发送同一份报表。

V2 Spec 和 ADR 需要定义服务端的提供商接口、配置模型、调度与重试边界。接口名称、数据库结构和 Server酱请求格式在冻结前不由路线图决定，编码代理不得仅凭“需要抽象”创建通用 `CommonService`、插件系统或未来平台脚手架。

### 4.4 AI 与业务写入边界

V2 默认继承以下可信边界，除非新的 ADR 和 Spec 经人工批准后明确改变：

- AI 不能标记视频完成、伪造可信进度、代替验活或修改观看心跳。
- AI 不能直接核销欠债、修改答题结果、生成报表事实或改写日终结果。
- AI 不能自动锁定计划，也不能绕过现有应用服务和所有权校验。
- 模型输出不是业务真相；所有写操作必须由确定性应用服务校验并可审计。

原型包含“把排期写入计划草稿”的候选交互。是否允许 AI 生成可编辑草稿、草稿覆盖哪些日期、怎样确认、怎样避免修改不可变项目，必须由 V2 专项 ADR 决定。没有该 ADR 前，编码代理不得实现任何 AI 计划写入。

### 4.5 V2 立绘继承规则

V2 立绘必须从 V1「毛线团团」的精灵表、动作模型、悬浮层、拖动、贴边、减弱动态效果和 Widget 测试基础上增量修改，不另起一套与现有学习伙伴并行的宠物系统。

V2 可以在获批设计中调整形象表现、对话入口、上下文提示、停靠方式和动作接线，但必须先明确：

- 哪些 V1 动作与交互继续保留。
- 哪些新增动作对应确定的产品状态。
- AI 请求期间、失败、等待、审阅等状态是否使用现有未接线动作。
- 点击、拖动、全屏贴边和打开助教面板之间如何避免手势冲突。
- 立绘关闭后 AI 助教是否仍可独立使用。

原型中的 3:4 动漫立牌、“林见夏”“周执”和连续完成后解锁等内容目前都只是示例，不得替代「毛线团团」基线，也不得在 V1 中提前实现。

### 4.6 V2 冻结前必须回答的问题

- AI 可以读取哪些用户数据，怎样最小化上下文并避免跨用户、跨课程泄露。
- 会话保存在客户端还是服务端，保留期限、删除语义、同步与备份边界是什么。
- 是否允许联网搜索；如果允许，使用什么受控接口、来源策略、超时和安全边界。
- 是否存在工具调用；如果存在，明确允许列表、输入校验、审计和失败降级。
- 是否允许生成计划草稿；如果允许，明确人工确认、版本冲突和不可变项目保护。
- 课程引用如何验证，模型无法找到依据时如何明确表达不确定性。
- 模型、费用、频率限制、并发、流式响应、内容安全和可观测性要求。
- 学习伙伴主动说话是否存在，默认值、打扰频率和无障碍行为是什么。
- V2 是否仍保持单实例 SQLite，新增会话与搜索数据量是否触发数据库迁移条件。
- 日报、周报的消息模板、长度限制和敏感字段裁剪规则是什么。
- 周报使用哪个周结束边界，首次启用、补发和跨时区修改怎样处理。
- Server酱配置如何校验，是否提供测试消息，SendKey 如何更新、撤销和安全回显。
- 投递失败的重试次数、退避策略、最终失败提示、人工重发和审计保留期限是什么。

## 5. V3.x.x：整体优化、性能、部署与个性化

### 5.1 版本目标

V3 面向已经稳定运行的产品做整体升级，不重做 V1/V2 已验证的业务闭环；同时扩展课程仅音频播放、画中画和资料阅读等新的学习载体。

### 5.2 服务端方向

- 基于真实监控和压测结果优化普通业务接口、心跳、报表、内容任务和媒体代理性能。
- 支持多实例或多集群部署、故障切换、滚动发布和容量扩展。
- 重新评估数据库、Session、任务队列、文件存储、内容任务协调、缓存和可观测性方案。
- 建立容量目标、服务等级指标、压测基线和恢复演练要求。

当前 V1 的 SQLite、本地附件、单进程 Worker 和本地 Session 设计与多实例部署存在直接冲突。进入 V3 前必须先通过 ADR 决定数据存储和协调方案；V1 设计规范已经把“需要运行多个后端实例”列为评估迁移 PostgreSQL 的触发条件。

多实例不等于必须拆微服务。V3 应先评估模块化单体能否继续满足需求，不能仅因为“多集群”就提前拆服务、引入 Redis、Kafka、Kubernetes 或同时维护 SQLite/PostgreSQL 双兼容。

### 5.3 客户端方向

- 统一并提升全 App 视觉质量、信息层级、动效和跨设备布局。
- 建立可演进的设计令牌和主题系统。
- 支持用户选择主题、背景及其他经过明确设计的个性化外观。
- 继续满足 Dynamic Type、减弱动态效果、最小触控区和非颜色唯一表达等可访问性要求。
- 对 iPhone、iPad 和 Android 做性能、启动速度、内存、播放器和长列表体验优化。

主题、背景和个性化配置在 V3 Spec 冻结前不定义具体选项、资源格式、下载方式或同步策略，也不在 V1/V2 预建主题框架。

### 5.4 媒体播放方向（已确认方向）

V3 增加课程仅音频播放和视频画中画（Picture-in-Picture，PiP）能力，作为整体媒体体验升级的一部分。

已确认的产品方向：

- 客户端可以对现有课程视频切换“仅音频播放”，只播放该课时的视频音轨，不渲染视频画面。
- 仅音频模式复用现有课程、课时、作战单项目、播放票据和学习记录，不创建独立音乐目录。
- 视频支持进入系统画中画模式，让用户离开当前页面后继续观看。
- iPhone、iPad 和 Android 保持一致的业务语义，平台差异只放在音频会话、系统媒体控制和 PiP 适配层。
- 媒体源、播放票据和外部服务凭据仍由服务端受控，客户端不得因此直接取得 Emby API Key。
- 课程仅音频播放与 PiP 不意味着支持离线下载；离线媒体如果未来需要，必须另行立项。

画中画与 V1“App 进入后台必须暂停视频”“后台状态不累计可信时间”的规则存在直接冲突。V3 开始实现前必须通过专项 ADR 和 Spec 明确：

- PiP 激活时是否属于可信前台观看，以及可信心跳如何校验。
- PiP 期间怎样触发和展示验活；无法完成验活时是否立即暂停。
- 从普通播放器进入 PiP、退出 PiP、锁屏、切换 App 和进程恢复时如何维持同一个观看会话。
- 画中画观看是否完成作战单、偿还欠债并进入有效学习时长。
- iOS/iPadOS 与 Android 系统能力不一致时采用什么降级行为。

课程仅音频播放在 V3 冻结前还必须明确：

- 是否支持后台播放、锁屏控制、耳机按键、来电/音频焦点中断和断点恢复。
- 仅音频播放能否推进同一课时的可信进度、完成作战单、偿还视频欠债并进入有效学习时长。
- 仅音频模式怎样执行心跳和验活；切到后台或锁屏后是否继续累计可信学习。
- 服务端复用现有 Emby 媒体代理与票据，还是为同一课时提供受控的音轨读取接口。
- 从视频切换到仅音频、再切回视频时，怎样复用同一个观看会话并保持位置一致。

该能力不是音乐 App，不包含歌曲或专辑目录、独立音乐媒体库、歌单、收藏、音乐推荐或面向娱乐音乐的播放功能。

V3 Spec 未冻结前，不得在 V1/V2 修改后台暂停规则、可信心跳、播放器状态机、平台权限或媒体依赖，也不得提前创建课程音频播放器或 PiP 抽象。

### 5.5 资料阅读闭环（已确认方向）

V3 增加以 PDF 为首个资料格式的阅读能力，使管理员可以在管理后台上传学习资料，用户可以在客户端选择资料、加入作战单并完成阅读。

已确认的产品方向：

- 管理后台提供 PDF 学习资料的上传、基础信息维护、启用和停用能力。
- 客户端提供资料目录、PDF 阅读器和继续阅读入口。
- 用户可以从作战单编排区选择资料，并把阅读任务加入当天作战单。
- 服务端保存用户的资料阅读进度和最后阅读位置，跨设备或重新打开后可以继续阅读。
- 阅读任务的状态、完成判断、日终结算和欠债生成必须由服务端决定，客户端不能直接把资料标记为可信完成。
- PDF 文件必须经过文件签名、格式、大小、所有权和安全路径校验；下载或读取使用受保护接口，不暴露服务端任意文件路径。
- 大型 PDF 必须流式传输或按需读取，不得把完整文件缓冲进服务端或客户端内存。
- V3 多实例/多集群部署时，PDF 原文件不能依赖某一个实例的临时目录；最终存储与备份方案必须和 V3 集群 ADR 一起确定。

“资料阅读”当前不自动包含以下能力：

- OCR、扫描件文字识别、AI 摘要、AI 问答或自动出题。
- 高亮、批注、书签、全文搜索、分享、打印或导出。
- 离线下载与离线阅读。
- Word、EPUB、图片集或其他资料格式。

这些能力只有在 V3 Spec 明确纳入并提供验收条件后才能实施，不能因为接入 PDF 阅读器而顺手增加。

V3 Spec 和专项 ADR 必须进一步确定：

- 资料是独立资源，还是必须关联课程、考试目标或章节。
- 作战单按页数、阅读时长、页码范围还是管理员定义的阅读单元进行规划。
- 怎样判定可信阅读完成，快速翻页、后台停留和重复阅读是否累计。
- 未完成阅读是否生成新的资料阅读欠债，以及欠债怎样偿还。
- PDF 更新或替换后如何保持历史作战单、进度、欠债和审计关系稳定。
- 密码保护、损坏、超大、扫描版和包含外部链接的 PDF 如何处理。
- iPhone、iPad 和 Android 的翻页、缩放、横竖屏、无障碍和真机验收标准。
- 文件存储、配额、备份、恢复、删除和多集群分发方案。

V3 Spec 未冻结前，不得新增作战单项目类型、阅读进度表、PDF 上传接口、文件存储依赖或客户端 PDF 插件。

### 5.6 V3 冻结前必须回答的问题

- 目标并发、吞吐、延迟、可用性、恢复时间和数据恢复点是多少。
- “多集群”指多实例、同城高可用、跨地域部署还是多租户隔离。
- PostgreSQL、共享文件或对象存储、Session 和任务协调如何迁移，怎样回滚。
- 媒体代理在集群中的带宽、会话黏性和播放票据校验方式。
- 主题与背景的内置、下载、缓存、跨设备同步和资源安全边界。
- 课程仅音频播放与画中画的可信学习语义、平台降级和真机验收范围。
- PDF 资料的规划单位、可信完成、欠债、版本替换、存储和备份规则。
- V3 是否包含新的产品能力；如果包含，必须单独进入需求评审，不能混入“性能优化”或“UI 美化”。

## 6. 从路线图进入开发的门禁

V2 或 V3 开始编码前必须依次完成：

1. 维护者明确宣布要启动的版本和本次范围。
2. 在 `docs/specs/` 新建对应版本的产品与技术设计规范，并标注状态。
3. 为改变既有边界的关键决策新增 ADR，例如 AI 权限、联网搜索、会话存储、计划草稿、多实例数据库和主题资源方案。
4. 在 `docs/plans/` 新建对应版本的 Implementation Plan，拆成可独立测试和提交的 Task。
5. 在 `docs/traceability/` 新建对应版本的需求—实现—验收追踪矩阵。
6. 由维护者人工批准 Spec、ADR、Plan 和 Traceability，并在文档中记录批准状态。
7. 编码代理只执行获批计划中的当前 Task，先写失败测试，再做最小完整实现。

建议的未来文件名：

```text
docs/specs/YYYY-MM-DD-shangan-v2-design.md
docs/plans/YYYY-MM-DD-shangan-v2-implementation-plan.md
docs/traceability/YYYY-MM-DD-shangan-v2-traceability.md

docs/specs/YYYY-MM-DD-shangan-v3-design.md
docs/plans/YYYY-MM-DD-shangan-v3-implementation-plan.md
docs/traceability/YYYY-MM-DD-shangan-v3-traceability.md
```

## 7. 路线图维护规则

- 未来方向、版本归属或版本顺序改变时，修改本文档。
- 已进入活动版本并获批的需求变化，修改该版本的 Spec、ADR、Plan 和 Traceability，不继续只改路线图。
- 原型和聊天内容可以作为设计输入，但不能直接成为实现要求。
- 不把路线图条目改成 checkbox，也不在这里记录代码完成状态，避免编码代理把未来方向误认为当前 Task。
- 不删除历史版本文档；被替代的决策应通过 ADR 和明确的替代说明保留审计链。
