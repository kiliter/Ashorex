# Web 后台运行时服务配置设计

**状态：** 待书面复核  
**日期：** 2026-08-30  
**范围：** Spring Boot 内部管理后台

## 1. 背景

当前 Emby、LLM、ASR 和 MCP 只从环境变量读取，管理员只能在运行状态页面查看“已配置/未配置”。本地开发和小规模自建部署每次修改配置都需要重新注入环境变量并重启服务，操作成本较高。

本设计在现有 Thymeleaf 管理后台中增加统一配置页。管理员保存后，新发起的外部服务调用立即使用新配置，不要求重启 Spring Boot。

## 2. 目标

- 在一个 Web 页面管理 Emby、LLM、ASR 和 MCP 配置。
- 数据库尚无运行时配置时，继续使用现有环境变量。
- 第一次通过后台保存后，SQLite 中的整份配置成为运行时来源。
- 保存成功后立即对新调用生效。
- API Key 和 Token 使用支持显示/隐藏的密码输入框。
- 保持 Flutter、业务 API、日志和错误响应不包含外部密钥。

## 3. 不做

- 不建设独立配置中心。
- 不做配置版本历史、审批流、灰度或回滚。
- 不加密 SQLite 中的外部密钥。
- 不增加连通性测试按钮。
- 不修改 Flutter，也不新增 `/api/v1` 接口。
- 不保证修改 Emby 配置时正在播放的视频无缝续播。

## 4. 页面设计

后台导航新增“服务配置”，页面路径为：

```text
/admin/settings/integrations
```

页面沿用现有移动端优先管理后台样式，包含四个配置区：

### 4.1 LLM

- Base URL
- API Key
- 模型名称
- 最大上下文 Token 数
- Temperature
- 请求超时

### 4.2 ASR

- Base URL
- API Key
- 模型名称
- 请求超时

### 4.3 MCP

- 服务 URL
- Bearer Token
- 允许工具名称列表
- 请求超时

### 4.4 Emby

- Base URL
- API Key
- 用户 ID

API Key 和 Token 以密码框渲染，并提供原生 JavaScript“显示/隐藏”按钮。页面打开时回填当前有效配置，包括首次启动时从环境变量取得的值。一次提交保存全部配置，避免出现跨配置区的部分更新。

## 5. 配置来源与数据模型

新增追加式迁移：

```text
V012__runtime_integration_settings.sql
```

新增单行表 `runtime_integration_settings`。固定主键为 `default`，保存全部字段以及 `updated_at`。不保存历史值。

配置来源规则：

1. 表中没有记录时，使用 `application.yml` 已映射的环境变量组成初始快照。
2. 管理员首次保存时，表单回填的整份配置写入 SQLite。
3. 表中存在记录后，数据库整份配置具有最高优先级；空字段也是明确配置，不再逐字段回退环境变量。
4. SQLite 在线备份会包含明文外部密钥。

## 6. 服务端组件

### 6.1 共享配置边界

运行时配置属于服务端公共基础能力，放在 `common.integration`，不放在 `admin`。AI、Emby 和管理后台只依赖明确的 `IntegrationSettingsProvider` 应用接口，避免业务模块反向依赖管理页面。

`RuntimeIntegrationSettingsRepository` 只负责查询和更新单行配置。Repository 不负责校验、运行时刷新或外部连接。

### 6.2 应用服务

`RuntimeIntegrationSettingsService` 负责：

- 启动时加载数据库配置或环境变量初始值；
- 校验管理员提交的整份配置；
- 在短事务内保存配置；
- 保存成功后原子替换内存中的不可变配置快照；
- 为 Emby、LLM、ASR、MCP 调用提供当前快照。

数据库保存失败时不得替换内存快照。

### 6.3 外部服务适配器

现有适配器不再在 Spring Bean 构造时永久捕获 `@Value`：

- LLM：每个新 AI 流按当前快照创建模型和只读 AI Service。
- ASR：每个转写切片开始时取得快照。
- MCP：按 AI 流的快照建立连接，流结束后关闭。
- Emby：同步、健康检查、播放信息和媒体代理请求读取当前快照。

AI 流和已经开始的转写切片继续使用开始时取得的快照。Emby HLS 的后续分片请求读取最新快照，因此页面明确提示管理员最好在无人播放时修改 Emby 配置。

## 7. 校验和错误处理

- Base URL 必须是完整 HTTP 或 HTTPS 地址，不允许用户名、密码、Query 或 Fragment；允许提供商必需的固定路径，例如 `/v1` 或 `/mcp`。
- 最大上下文 Token 数范围为 1,024 到 1,000,000。
- Temperature 范围为 0 到 2。
- LLM 超时范围为 1 到 600 秒，ASR 为 1 到 1,800 秒，MCP 为 1 到 120 秒。
- 允许某一服务的关键字段不完整；该服务保存后显示“未配置”，调用时继续返回现有安全错误。
- 任一字段校验失败时不保存任何字段，页面显示中文字段错误。
- 不在校验错误、日志或异常页面中输出密钥、Token 或第三方响应正文。
- 远端地址暂时不可达不阻止保存，实际调用按现有稳定错误安全失败。

## 8. 安全边界

- 页面仅允许已认证 ADMIN Session 访问。
- 写入继续使用 Spring Security CSRF。
- 配置页面响应设置 `Cache-Control: no-store`。
- 密钥可以由管理员在该页面显示，但不得进入 Flutter、`/api/v1`、运行状态页面、日志或错误响应。
- 不把配置值写入请求日志；表单失败时只返回安全错误说明。
- Emby 和 MCP 仍只接受后台保存的固定 HTTP/HTTPS 目标，不允许普通用户按请求覆盖目标地址。

## 9. 测试

### 9.1 单元测试

- 数据库记录与环境变量的整份配置优先级。
- URL、上述精确数值范围和不完整配置校验。
- 保存失败时保留旧内存快照。

### 9.2 集成测试

- Flyway 创建单行配置表并可持久化。
- ADMIN 可读写，匿名和 USER 被拒绝。
- 缺少 CSRF 的保存请求被拒绝。
- 页面渲染密码字段、显示/隐藏按钮和 `no-store`。
- 保存后 LLM、ASR、MCP 和 Emby 的新调用读取最新配置。
- 配置和密钥不出现在运行状态 DTO、日志断言或业务 API 响应中。

### 9.3 验证命令

```bash
cd apps/server
./mvnw -Dtest='*RuntimeIntegrationSettings*,AdminSecurityTest' test
cd ../..
make format
make verify
```

## 10. 完成标准

- 管理员可以在一个页面编辑并保存四类配置。
- 密码字段可以显示和隐藏。
- 保存后无需重启，新调用立即使用新配置。
- 环境变量初始配置仍兼容。
- 配置校验、权限、CSRF、禁止缓存和运行时刷新均有自动化测试。
- 全量验证通过，仓库中没有新增真实密钥。
