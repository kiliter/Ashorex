# Flutter 服务端地址配置设计

**状态：** 已批准  
**日期：** 2026-08-30  
**范围：** 上岸 Flutter iOS App 的服务器连接配置与本地开发启动

## 1. 背景

当前 App 在 `bootstrap` 中通过 `API_BASE_URL` 编译参数创建单一 `ApiClient`，并将由它构造的 Repository 注入 Riverpod。这个方式适合固定环境构建，但在本地开发、局域网真机调试或切换自建服务时，需要重新构建 App，使用不便。

本变更只增加客户端连接目标配置能力，不改变任何服务端业务规则，不引入本地业务数据库，也不允许客户端绕过服务端状态机。考试目标、计划、欠债、可信观看、答题、报表和 AI 数据仍以当前所连接服务端为唯一业务真相。

## 2. 目标与非目标

### 2.1 目标

- 未登录用户可从登录页右上角进入“服务器设置”。
- 默认地址继续由 `API_BASE_URL` 编译参数提供。
- 用户保存的地址持久化在 `SharedPreferences`，并优先于编译默认值。
- 保存前验证地址格式并检查服务端健康状态。
- 地址切换后清除旧服务器 Token，重新创建全部网络依赖并回到登录状态。
- 登录页展示当前服务器主机，避免用户误连环境。
- 支持本机模拟器、局域网真机和 HTTPS 自建服务。

### 2.2 非目标

- 不提供本地 Mock 服务。
- 不缓存或离线修改业务数据。
- 不自动迁移不同服务器之间的 Token 或业务数据。
- 不保存多个服务器配置列表。
- 不允许在地址中嵌入用户名或密码。
- 不修改服务端认证、API 路径或业务状态机。

## 3. 方案选择

采用“保存后重建 App 依赖图”方案。

未采用的方案：

- 保存后要求用户手动重启 App：实现简单，但切换反馈不明确，容易继续使用旧连接状态。
- 直接修改 Dio 的 `baseUrl`：播放器 Repository 还持有独立的基础 URI，局部修改可能导致不同请求连接到不同服务器。

重建依赖图可以一次性替换 `ApiClient`、认证控制器和全部 Repository，确保连接目标一致。

## 4. 架构与组件

### 4.1 `ServerConfiguration`

不可变值对象，保存规范化后的基础地址：

```text
scheme://host[:port]
```

校验规则：

- Scheme 只能是 `http` 或 `https`。
- Host 不能为空。
- 不允许用户名、密码、Query 或 Fragment。
- 不接受 API 子路径；所有接口仍由客户端附加 `/api/v1`。
- 保存时移除末尾 `/`。

### 4.2 `ServerConfigurationStore`

使用 `SharedPreferences` 保存用户覆盖地址。编译默认值不写入存储。

读取优先级：

```text
用户已保存地址
→ API_BASE_URL 编译参数
→ http://127.0.0.1:8080
```

此存储只保存非敏感连接地址，不保存 Token、密码或服务端密钥。

### 4.3 `ServerHealthChecker`

使用独立、无认证的短生命周期 Dio 请求：

```text
GET {baseUrl}/actuator/health
```

成功条件为 HTTP 2xx 且响应中的 `status` 为 `UP`。连接和接收均使用短超时。健康检查失败时返回可操作的中文错误，不覆盖原地址。

### 4.4 `ApplicationBootstrap`

根组件负责：

1. 读取当前服务器配置。
2. 创建 Token Store、ApiClient、AuthController 和全部 Repository。
3. 通过 Riverpod overrides 构建 App。
4. 接收服务器地址变更事件。
5. 清除 Token、释放旧控制器并用新配置重建依赖图。

地址切换属于服务器身份边界变化，旧 Access Token 和 Refresh Token 必须在创建新客户端前清除，不能发送到新服务器。

### 4.5 登录页入口

登录页右上角提供“服务器设置”按钮。登录页正文显示当前服务器主机和端口。配置页包含：

- 服务端地址输入框。
- 当前生效地址。
- 本机模拟器与局域网真机提示。
- “测试并保存”按钮。
- 连接、校验和保存状态。

保存成功后关闭配置页，根组件重建依赖，登录页显示新地址。

## 5. 数据流

```text
App 启动
→ 读取用户覆盖地址或编译默认地址
→ 创建网络依赖
→ 展示登录页与当前服务器

用户打开服务器设置
→ 输入地址
→ 本地格式校验
→ 请求 /actuator/health
→ 健康检查通过
→ 保存 SharedPreferences
→ 清除旧 Token
→ 重建网络依赖
→ 返回未登录状态
```

## 6. 错误处理

- 格式错误：在输入框下显示具体校验原因，不发起网络请求。
- DNS、连接拒绝或超时：保留原地址，显示“无法连接服务器”。
- 健康接口非 2xx 或状态不是 `UP`：保留原地址，显示“服务端健康检查未通过”。
- 持久化失败：保留原地址和当前登录状态，显示“地址保存失败”。
- 重建依赖时发生异常：回退到保存前地址，不留下半切换状态。

所有错误信息不得包含 Token、完整堆栈或敏感响应正文。

## 7. 开发环境

本地 Spring Boot 服务使用仓库 Maven Wrapper 启动，监听 `8080`，数据库写入工作区内的开发数据目录。开发密钥通过当前 Shell 环境注入，不写入仓库。

模拟器可使用：

```text
http://127.0.0.1:8080
```

物理 iPhone 必须使用 Mac 的局域网地址或可访问的 HTTPS 域名，不能使用 iPhone 自身的 `127.0.0.1`。

## 8. 安全边界

- 切换服务器必须清空当前 Token。
- 地址不得包含 Basic Auth 用户名或密码。
- App 仍不接触 Emby、LLM、ASR 或 MCP 密钥。
- Release 保留服务器设置入口，以支持自建部署。
- HTTP 仅用于本机或局域网开发；生产环境继续要求 HTTPS。
- 健康检查不携带 Authorization Header。

## 9. 测试与验收

自动化测试：

- 地址解析、规范化和非法输入拒绝。
- 用户地址优先于编译默认地址。
- 健康检查成功后才保存。
- 健康检查失败不覆盖原地址。
- 切换地址清除 Access Token 和 Refresh Token。
- 依赖重建后认证状态为未登录。
- 登录页展示当前服务器并能打开配置页。

人工验收：

1. 启动本地 Spring Boot 服务。
2. App 默认连接 `http://127.0.0.1:8080`。
3. 登录页打开服务器设置。
4. 无效地址被拒绝。
5. 不可达地址不会覆盖原配置。
6. 保存可达地址后无需重启 App。
7. 使用新服务器账号成功登录。
8. 再次切换服务器后旧登录状态被清除。

## 10. 完成标准

- 设计对应的单元测试和 Widget 测试通过。
- `make format && make verify` 通过。
- 本地服务实际启动，`/actuator/health` 返回 `UP`。
- iOS 构建成功。
- API 合同不发生变化。
- 未新增本地 Mock、业务数据缓存或服务端规则分叉。
