# 管理后台移动端 UI 设计

## 目标

将现有无样式的 Thymeleaf 管理后台改造成移动端优先、视觉统一且可直接操作的“岸线工作台”。本次只调整表现层，不修改后台业务行为、权限、CSRF 或数据接口。

## 设计方向

后台面向在手机上快速查看运行状态、维护用户和课程的管理员。视觉采用深海军蓝、潮汐蓝和低饱和浅灰构成的清爽工作台风格，避免通用 Bootstrap 后台的模板感。

颜色令牌：

- Paper `#F6F8FC`：页面背景。
- Ink `#172033`：正文与主要标题。
- Harbor `#23437A`：品牌区域和导航。
- Tide `#2F6FED`：主要操作与当前导航。
- Foam `#DDF3EA`：正常和成功状态。
- Signal `#C9564B`：错误、禁用和风险状态。

字体角色：品牌使用系统 Rounded 字体，正文使用 Apple 系统中文字体，运行数据使用系统等宽字体。所有控件保持至少 44 像素高度，并提供清晰的键盘焦点。

## 页面结构

移动端以顶部品牌栏和可横向滚动的功能导航为主，内容使用卡片、字段网格和可横向滚动的数据表。桌面宽度达到 960 像素后切换为左侧固定导航与右侧内容区域。

统一覆盖以下页面：

- 登录。
- 运行状态。
- 用户管理。
- 课程管理。
- 课时管理。
- 课后题列表。
- 课后题编辑。
- 视频转写。

登录页使用独立的品牌介绍卡与登录表单。后台页面共享品牌、导航和退出入口；当前页面通过文字、底色和左侧标记共同表达，不只依赖颜色。

## 实现方式

1. 新增本地静态资源 `/assets/admin.css`，不依赖 CDN、Node 或外部字体。
2. 新增 Thymeleaf 公共片段，统一页面 `<head>`、品牌栏和主导航。
3. 保留现有表单 action、字段名和 CSRF 自动字段，仅增加语义化容器与样式类。
4. 表格在窄屏内横向滚动；重复操作项使用卡片列表，避免输入控件被压缩。
5. 错误、空状态和配置状态使用明确中文文案与状态标签。

## 安全与错误处理

- 样式文件位于 `/assets`，允许登录前匿名读取，不暴露任何业务信息。
- 管理页面仍受现有 ADMIN Session 权限保护。
- 登录和业务表单仍由 Spring Security 提供 CSRF 保护。
- 不在 HTML、CSS 或日志中写入密码、Token、密钥或远端凭据。

## 验证

1. 测试匿名用户能够读取样式文件，登录页包含本地 stylesheet。
2. 测试管理员页面包含共享导航和移动端 viewport。
3. 运行 `AdminSecurityTest`，确认登录、权限和 CSRF 行为不变。
4. 运行 `make verify`。
5. 在手机宽度和桌面宽度分别检查登录、运行状态、用户、课程和转写页面。
