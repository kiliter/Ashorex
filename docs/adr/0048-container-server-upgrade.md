# ADR-0048：独立容器执行服务端自动升级

- 状态：已接受（用户已批准方案、host 网络及独立工作树实现并经 CI 合并）
- 日期：2026-09-09

## 决策与范围

扩展 V2 运维范围：同一镜像提供 server 与 updater 两个角色，只有 updater 可访问 Docker socket。Linux 部署两者均用 host 网络。updater 无监听端口，以共享目录接收后台任务，默认关闭自动升级；可设置 IANA 时区与每日执行时间，支持检查、预下载、立即升级。只信任 kiliter/Ashorex 正式 Release 的 server-update.json 和 ghcr.io/kiliter/ashorex-server 的 digest。

updater 使用 Docker Engine API，按既有容器配置、固定命名卷及 host 网络重建 server；不自动升级自身，不接受浏览器传入镜像、命令、路径或 URL。Docker socket 权限等同宿主机管理权限，部署保持非 root UID，通过附加 socket GID 授权。HTTP(S)_PROXY 只影响清单查询；镜像拉取由 daemon 执行，需独立配置其代理。

## 升级与恢复边界

先拉镜像和核验协议标签，再设置维护标志、停止旧服务。使用临时容器在静止的数据上执行既有 SQLite/附件备份和完整性校验，升级备份独立保留。持久化原容器配置、旧镜像 ID、目标 digest 与阶段；文件锁串行，任务文件原子提交。新服务维护期间阻止所有业务请求和自动催办，只有健康与版本探测例外，后台暂时断线并自动重连。校验健康及实际构建版本后先记录验收完成，再解除维护；此后绝不自动恢复数据库快照。

验收前失败则停新服务、恢复本次快照和附件、启动旧镜像并验收。备份未成功时只重启旧容器。updater 重启后按持久化阶段恢复，已验收完成的版本只解除维护，不能回退数据。恢复失败保留维护标志和故障状态，不自动无限重试。同一失败版本禁止定时重试，管理员可明确再次发起升级。

第一版不提供开放业务后的自动回退按钮：数据库兼容性与快照后的写入无法由镜像版本判断，需按运行手册人工处理。状态、日志仅含安全中文阶段和版本，不返回 Docker inspect、部署凭据或绝对路径。保留升级快照不自动删除，由管理员确认清理。

## 兼容性与首次接入

不改变 App API 字段、枚举与状态机，不需要升级 App。短暂维护返回 HTTP 503 与 SERVER_UPGRADING、Retry-After；旧 App 按既有网络失败/进度队列重试，不返回伪成功。不关闭全屏催办、不清理离线队列。首次通过更新后的 deploy.sh 安装带维护协议的 server/updater 和共享卷；拒绝更新不支持协议的旧镜像。所有公开版本清单默认不允许自动安装，维护者在发布源文件显式确认自动资格及旧 App 兼容性后才开启。

## 验收

独立单元测试覆盖清单信任、版本比较、拉取失败不停止服务、备份失败、启动失败恢复、断点恢复、验收完成不回退、重复任务和时区调度；测试不启动真实数据库。后台 Controller 覆盖输入验证和安全状态投影，维护过滤器覆盖旧版请求 503 和健康通道。真实 ApplicationContext 启动须 UP；Docker 真实镜像升级/恢复 Smoke 在 CI 执行并作为合并门禁。

## 后续客户端安装包分发约定

用户确认 Android APK、iOS 无签名 IPA 经 Spring Boot 流式中转 GitHub Release，支持 Range，禁止全包内存缓冲；iOS 由用户下载后使用轻松签自行签名。该接口与客户端更新页面属于后续客户端在线更新任务，本 T48 不实现。

## 2026-09-10 页面高度修正

版本与升级页沿用后台视口高度约束，标题固定，宽屏将版本卡片与设置、结果卡片分列；窄屏恢复单列。仅内容区域在空间不足时滚动，长更新说明独立限高，确认框在矮窗口中可滚动，禁止直接裁掉操作。属于 T48 页面适配修复，不改变升级接口与行为。
