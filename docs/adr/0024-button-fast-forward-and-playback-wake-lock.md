# ADR-0024：按钮快进视为通过，播放期间保持屏幕常亮

- 状态：已接受（2026-09-07 维护者明确确认允许按钮跳过未看内容，跳过内容视为已通过但不增加实际学习时长）
- 日期：2026-09-07
- 对应任务：Task 30

## 背景

原规范第 4.5 节禁止任何方式跳入未验证区间，Task 10 允许在可信区间拖动，复习课时允许全片拖动。这与此次确认的“只通过按钮快进，不支持进度条拖拽”冲突。播放器也尚未接入已有的屏幕常亮能力。

## 决策

- 普通学习每次点击快进按钮前进 10 秒，最远到视频末尾；服务端先验证当前播放事实，再授权固定步长，客户端只能在响应成功后跳转。
- 跳过部分视为已通过，推进 `maxVerifiedPositionMs`，沿用该字段参与完成阈值、计划、续播和视频欠债对账；字段保留历史名称，其含义扩展为服务端认可的通过位置。
- 跳过的时长不增加 `verifiedWatchMs`。点击前真实播放的时间仍按原心跳策略计算。日报、周报的有效学习时长不因跳过内容增加。
- 连续点击允许逐次跳过，可能在实际学习时长较少时完成视频，这是本次确认的产品行为；必答课后题规则保留。
- 快进和心跳共用单调序号，重复请求不重复推进。服务端校验归属、会话状态、前台状态和验活状态；待验活不能快进。跨过验活检查点仍触发验活，达到完成阈值时按既有规则结束。
- 正常心跳继续拒绝未经授权的位置跳跃，不能把任意目标位置当成按钮快进授权。
- 普通学习与复习的进度条均只展示，不支持点击、拖拽或无障碍调节定位。快退仍为每次 10 秒；复习快进在完整视频范围内执行，不改变原有复习审计边界。
- 前台播放期间使用已有 `ScreenWakeLock` 保持屏幕常亮；暂停、验活、连续心跳失败暂停、播放完成、切后台和退出释放常亮。全屏切换复用同一个播放会话和常亮生命周期。

## 后果

- 新增固定步长快进 API 并同步 OpenAPI；保留现有持久化字段，不引入迁移或未观看区间存储。
- 客户端必须与支持该接口的服务端配套更新。接口不可用时显示失败，不在本地擅自跳过。
- 本次替代旧规范中“所有未看区间快进均拒绝”和“复习可拖动”的交互限制，其他学习状态机保持原规则。

## 被否决的方案

- 只解除客户端限制：下次服务端心跳会纠偏，且无法区分真实播放与主动跳过。
- 直接扩大心跳容差：任意跳跃会被错误计入实际学习时长。
- 记录跳过区间并要求补看：与维护者已确认的“跳过视为通过”不符。
