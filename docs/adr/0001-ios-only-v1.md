# ADR-0001：V1 仅交付 iOS 客户端

- 状态：已接受
- 日期：2026-08-27

## 背景（Context）

上岸 V1 的目标是用最小团队完成考试目标、每日计划、可信学习、欠债和复盘闭环。首批用户使用 iPhone，且真实视频播放、App 生命周期、Keychain 和交互验收都需要优先针对一个平台打磨。同步建设多个客户端会分散测试与交付能力。

## 决策（Decision）

V1 只交付 Flutter iOS App，最低支持 iOS 16。业务规则、状态机和数据真相统一放在服务端，API 不包含 `/ios` 等平台专用路径。Flutter 工程暂不创建 Android 平台文件，也不创建 PC Web、macOS 或 Windows 客户端。

## 后果（Consequences）

- 可以集中验证 iPhone 上的视频播放、后台暂停、可信进度、随机验活和安全存储。
- 服务端 API、DTO 与 SSE 协议仍保持平台中立，为未来平台复用保留可能。
- V1 不提供非 iOS 客户端；未来新增平台必须单独评估、更新规范并安排验收。
- 实现过程中不得以“未来可能需要”为理由创建空客户端或平台抽象。

## 被否决的方案（Rejected Alternatives）

- 同时交付 iOS 与 Android：增加设备矩阵和播放器差异，不符合 V1 交付能力。
- 建设 PC 学习 Web：偏离移动端监督闭环，并增加一套 UI 与播放适配。
- 创建原生 Swift 客户端：无法利用既定 Flutter 技术基线和未来移动端复用能力。
