# ADR-0035：高保真原型与冻结规范的 6 处矛盾收敛

- 状态：已接受
- 日期：2026-09-08
- 相关：ADR-0025（Todo 中心模型）、ADR-0028（督学角色与快照）、ADR-0031（V2 数据库基线）
- 影响文档：`docs/prototypes/shangan-v2-prototype.html`、`docs/specs/2026-09-07-shangan-v2-design.md`

## 背景

仓库里有两个「事实来源」：

- `docs/prototypes/shangan-v2-prototype.html` 是 **UI 事实来源**（AGENTS.md「UI 规则」）；
- `docs/specs/2026-09-07-shangan-v2-design.md` 是 **功能边界事实来源**（AGENTS.md「必读文档与需求来源」）。

Flutter 端逐屏比对时发现 6 处两者互相矛盾：原型画了规范没有、甚至规范明确排除的元素，或者原型自身不自洽。
这类矛盾不消除，后续每次照原型实现都会撞上规范红线，或者照规范实现后又被判定「和原型不一致」。
按 AGENTS.md「范围变更流程」，本 ADR 记录冲突、裁定与最小变更。

## 裁定原则

按 AGENTS.md「决策优先级」：

1. 学习数据与状态正确 —— 会导致进度 / 时长丢失的，以数据正确为准；
2. 规范明确排除的能力（AI 内容生产、可信播放、欠债……）以规范为准；
3. 需要改动已发布数据库基线（`V001__shangan_v2_baseline.sql`，append-only）的，成本远大于收益；
4. 纯视觉差异以原型为准。

四条都指向同一结论：**修原型 + 在规范里把边界写成明文**，不扩大 V2 范围。

## 6 处冲突与裁定

| # | 原型屏 | 原型画了什么 | 冲突 | 裁定 |
|---|---|---|---|---|
| 1 | 3-1 播放页 | 播放控制条上的「定时关闭」胶囊（睡眠定时） | 规范全文（含 §10.7 播放）没有睡眠定时；无人观看时继续计时与「`watchedMs` 只在前台真实播放时累加」的口径冲突 | **删原型元素**，§10.7 写明播放控制项只有拖动、±10 秒、倍速、全屏 |
| 2 | 4-3 课程详情 | 说明文字「可直接播放（不加入待办）」+ 每个课时行尾的播放按钮 | 进度只能走 `POST /todos/{id}/progress`，`(todoId, clientSeq)` 是幂等键；无 Todo 播放会静默丢弃 `positionMs` 与 `watchedMs` | **删「直接播放」语义**，行尾按钮改为「加入今日待办」；§10.3 / §10.7 写明播放必须挂在 Todo 上 |
| 3 | 2-4 新建待办 | 「加入今日」开关，副标题「关闭则只存入待办池」 | `todos.local_date TEXT NOT NULL`；规范 §5.4 定义 `localDate` 是「今日 / 历史某天」的唯一依据，没有待办池；支持无日期状态要改已发布的 V001 baseline | **删开关**，§5.4 写明没有待办池，推后用顺延、预排用未来日期 |
| 4 | 9-6 学员报告 | 「主要问题」「建议动作」两行自动诊断 | 规范 §14 的学员报告只有时长 / 完成率 / 删除次数 / 回应率 / 课程分布；自动生成诊断与建议是 AI 内容生产入口，紧贴 §2.1「不实现任何 AI 能力」 | **删两行**，§14 写明只呈现事实指标，解读由督学人写在一键督学文本里 |
| 5 | 9-6 学员报告 | 分组标题右侧「导出」链接 | 规范 §10.6 督学端无导出端点；CSV 导出只属于管理后台（8-8 删除流水） | **删链接**，§10.6 / §14 写明督学端无导出入口 |
| 6 | 5-3 月度热力图 | `.heat` CSS 定义 `l1`–`l4` 四个时长色阶，图例只标 2 个时长档（「1 小时内」用 `l2`、「3 小时以上」用 `l4`），`l1` 与 `l3` 没有任何图例说明；截图说明写「分 4 档」 | 规范 §9 只定义 3 个时长档（`<1h` / `1–3h` / `>3h`）；原型自身也不自洽（4 个色阶 / 2 条图例） | **原型收敛为 3 个时长档**（`l2` / `l3` / `l4`），删除多余的 `l1` 色阶，图例补齐「1 – 3 小时」；§9 写明时长只有 3 档且图例必须标全 |

第 6 项是原型自身不自洽，不是原型与规范的取舍问题；保留 `l2`/`l3`/`l4` 三个类名而不是重命名为 `l1`–`l3`，是为了让色值与 Flutter 既有的 `ShanganHeatColors.l2/l3/l4` 一一对应，避免无意义的实现改动（`l1` 仍被日历月视图使用，只是不再用于热力图）。

## 被删除 / 修改的原型元素清单

删除：

1. 3-1 播放页：`<span class="vtool">…定时关闭</span>`（1 处）。
2. 2-4 新建待办：「加入今日 / 关闭则只存入待办池」整块开关行及其上方分隔线（1 处）。
3. 9-6 学员报告：`<a>导出</a>`（1 处）。
4. 9-6 学员报告：`主要问题`、`建议动作` 两条 `.kv` 行（2 处）。
5. 5-3 热力图：`.heat i.l1{...}` CSS 规则（1 处）。

修改：

6. 4-3 课程详情：5 个课时行行尾图标 `#i-play` → `#i-plus`（材料行原本就是 PDF 图标，未动）。
7. 5-3 热力图：格子里 4 处 `class="l1"` 改为 `class="l2"`，图例新增「1 – 3 小时」（`#5A8FD1`）。
8. 说明文案（`frame-cap`，属注解不属屏内 UI）：3-1 注明无睡眠定时；4-3 注明播放必须先加入今日待办；2-4 注明保存即落在 `localDate`、无待办池；5-3 注明时长分 3 档；9-6 注明只呈现事实指标、无导出。

未动：管理后台 8-8「导出 CSV」（规范 §13 允许），以及所有与本次冲突无关的屏。

## 规范补充的位置

- §2.1 非目标：新增「只出现在原型里的四项越界元素」表，指向各自章节。
- §5.4 Todo：`localDate` 为 `NOT NULL`，无待办池，新建面板无「加入今日」开关。
- §9 统计口径：热力图 5 种状态、时长 3 档，图例必须标全，不得出现无图例说明的颜色。
- §10.3 课程库：课程库 / 详情只读，课时行唯一写操作是加入今日待办。
- §10.6 督学端：无导出端点；`/supervisor/report` 不返回诊断或建议文本。
- §10.7 播放：播放必须挂在 Todo 上；播放控制项白名单；不提供睡眠定时。
- §14 督学端功能清单：学员报告只呈现事实指标，无导出入口。

## 影响

- Flutter 端**无需改动**：实现当初是照规范落的地，本次修正把原型拉到与实现一致（课程详情行尾为加号、无睡眠定时、无「加入今日」开关、报告无诊断与导出、热力图 3 个时长档且图例 5 项齐全）。
- 服务端与 OpenAPI 契约不变：没有新增或删除端点，只是把「不存在的端点」写进规范说明。
- 数据库不变：不触碰 append-only 的 V001 baseline。
- 后续任何「原型上有但规范没有」的元素，按本 ADR 的原则处理：先判是否触及数据正确性或非目标，再决定改哪一边，并在规范里留下明文边界。

## 备选方案

- **按原型扩范围实现**（加睡眠定时、无 Todo 播放、待办池、报告诊断与导出）：直接违反 §2.1 非目标与 append-only 迁移策略，其中无 Todo 播放还会静默丢失学习数据，已否决。
- **只删原型元素、不改规范**：下一次读原型的人仍会重新提出同样的诉求，边界没有留痕，已否决。
- **把热力图改成 4 个时长档**：需要同时改规范 §9、实施计划 T-Stats 的分档定义与 Flutter 分档逻辑，收益仅为色阶更细，已否决。
