# ADR-0038：课时待办去重与历史未完成顺延确认

- 状态：已接受（2026-09-08 用户确认）
- 覆盖：Spec 5.4 原「同日允许重复」规则；关联 T07 / T24、原型 2-2

## 决策

1. 同一用户、日期和课时已存在相同目标进度的 Todo 时，跳过重复添加，包括已完成项、批内重复与请求重试；不按标题或当前观看进度去重。
2. 同日已有未完成课时但目标不同，先确认复用原项，目标取原目标与本次目标的较高值，已看位置和时长不变；不确认则跳过。已完成项不自动重新打开。
3. 批量提交逐项处理重复，不因某条重复而中断其他正常项；返回新增、顺延、复用、跳过数量及逐项原因。
4. 目标日期之前存在相同课时未完成 Todo 时，预览列出原日期、目标与观看位置。用户确认后顺延选中的原 Todo，保留身份、进度、时长、备注、附件，目标取原目标与本次目标的较高值；不自动创建第二条。多条历史重复时每个课时最多选择一条，不合并或删除剩余记录。
5. 历史项可以不勾选；不勾选就跳过该课时，不创建新记录。取消预览不写任何数据。已完成的历史 Todo 不阻止跨日期复看。
6. 提交时重新校验归属、日期、状态与课时，历史项已变更则返回冲突要求重新预览；已顺延到目标日期的重试跳过，不再次移动。整个提交为短事务，不包含外部网络请求。
7. 原创建接口同步防重；不新增数据库唯一索引，不清理或合并现存重复数据。保留 SQLite 单实例事务边界，禁止跳过确认暗中顺延。

## API 与 UI

- POST `/api/v1/todos/course-additions/preview`：`{items}`，返回逐项 NEW / EXISTING / TARGET_CONFLICT / HISTORY，含可复用的原项列表（今日不同目标或历史未完成）。
- POST `/api/v1/todos/course-additions`：`{items,reuseTodoIds}`，返回 created / deferred / reused / skipped 和逐项处理结果。
- 课时选择页标注当日已添加，仍可选中以确认提高目标；批量提交先预览，有重复或历史时弹出可滚动确认框，历史项按课时单选，提供跳过。确认前展示原目标与最终较高目标，并说明保留已有记录；最终反馈三类计数。

## 验收

单项与批内重复、重放、不同用户/日期、同日目标冲突、历史项未确认不移动、确认后 ID 与记录保留、多条历史选择、已完成历史可复看、过期或越权确认拒绝、当日数量限制、取消确认不写入；只运行相关窄测试。
