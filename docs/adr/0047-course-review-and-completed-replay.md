# ADR-0047：重复课时复习待办与已完成视频回放

- 状态：已接受（2026-09-09 用户确认并授权直接合并 main、CI 通过后发布）
- 关联：Spec 5.4、T07 / T08 / T24 / T25、原型今日待办与课时添加页。
- 本 ADR 覆盖 ADR-0038 对新版主动重复添加的限制；缺省请求保留旧版行为。

## 冲突与变更

ADR-0038 要求同日相同课时跳过或复用，不允许新增重复项；今日已完成行只进入完成详情。新需求允许主动新增重复视频并标记为“复习”，也允许不新增待办直接回放今日已完成视频。

## 决策

1. 用户再次添加已经安排过的相同课时，可以选择“新增复习待办”；原项是否完成均不阻止新增。重复按当前用户与稳定课时 ID 判定，不按标题判定。跨日再次安排同一课时也标记为复习。历史记录不自动改标记。
2. 复习仍是课程 Todo，额外展示“复习”标记，不新增 Todo 类型或状态。新 Todo 使用独立 ID，从 TODO、零播放进度、零本轮观看时长开始，不复制原项的备注、附件或完成记录；课时累计观看记录保留。
3. 复习沿用课程目标进度与完成规则，参与待办数量、统计及未完成催办。保留单日数量限制。重复添加一次生成一轮，批内误重复与同一请求重试不能多建；新的主动添加才产生下一轮。
4. 添加确认框保留原有复用选择，明确新增复习与复用原项的区别。取消不写数据。
5. 今日已完成且来源可用的课程提供“回放”按钮，从头播放，不创建 Todo、不撤销 DONE、不重置最远进度、不改变原完成时间或重复增加完成次数。原有完成详情、备注与附件入口保留。
6. 回放按现有前台实际经过时间累计观看时长，暂停与后台不计时；沿用进度事件幂等及断网队列。回放结束后刷新今日数据。来源下架时不进入播放器，展示既有不可用提示。

## 兼容与发布

- 新版添加请求显式表达新增复习意图并携带稳定请求标识；缺省保持 ADR-0038 的旧行为，旧 App 的请求重试不会意外新增复习。
- 复习标记作为增量响应字段，旧 App 可忽略；沿用 COURSE 与既有状态枚举，旧 App 仍可播放与完成复习 Todo。
- 数据库只追加迁移，不修改已发布 baseline；现存 Todo 默认普通课程。请求幂等记录需要按既有用户删除边界清理。
- 先发布兼容服务端，再发布 App。旧 App 不强制升级，但使用新增入口需要升级。客户端回退仍能使用旧接口；已新增学习数据保留。

## 实施与验收

1. 同步冻结 Spec、Plan、追踪表与 UI 原型。
2. 服务端实现复习创建、持久标记、请求幂等与 DTO，更新 OpenAPI。检查旧请求、不同用户隔离、同日与跨日复习、零进度、单日上限及重试不多建。
3. App 添加确认流程增加新增复习选项，列表显示复习标记；已完成课程提供独立回放入口并保留详情操作。
4. 窄测试覆盖选择与取消、复习首播不继承旧位置、DONE 回放不重复完成、实际时长及离线重放、不可用来源。运行受影响文件静态分析。
5. 迁移后清理旧构建产物，真实启动并检查健康 UP；全量验证交 GitHub CI，物理设备验证播放。

## 验证记录

- 相关服务端窄测试覆盖旧版去重、复习零进度、批内折叠、回执重试及内容冲突；Flutter 覆盖批量复习确认、取消、响应丢失重试与已完成视频从头回放。
- 通过根目录启动器启动独立临时服务，V010 迁移完成，健康端点 UP。真实 API 验证普通批量添加、已完成与未完成项新增复习、并发相同请求只建一批、旧版请求保持跳过、复习零进度、回放保留完成时间与完成次数；完整性和外键检查通过。
- 发布版本 v2.4.0；本地不运行全量验证，main 与版本标签交 GitHub CI。物理设备播放验收仍由用户执行。

## 2026-09-10 修订

本 ADR 第 5 条从头回放但不重置待办进度的行为由 ADR-0050 替代：明确确认后只重置当前待办进度，保留课时历史及完成记录，并记忆新轮次的位置。
