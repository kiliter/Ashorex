# ADR-0005：客户端允许配置服务端地址

- 状态：已接受
- 日期：2026-08-30

## 背景（Context）

上岸 App 原先只在编译时通过 `API_BASE_URL` 确定服务端地址。本地模拟器、局域网真机和自建部署需要连接不同服务，若每次切换都重新构建 App，会降低开发和验收效率。服务端地址不是业务数据，也不包含 Emby、LLM、ASR 或 MCP 密钥。

## 决策（Decision）

登录页右上角提供未登录可访问的“服务器设置”。用户输入的完整 HTTP/HTTPS 基础地址经格式校验和 `/actuator/health` 健康检查后，保存到 `SharedPreferences`，并优先于编译参数 `API_BASE_URL`。

本地开发服务统一监听 `18080`，Flutter 未传入 `API_BASE_URL` 时默认连接 `http://127.0.0.1:18080`。生产部署仍可通过环境变量覆盖端口和公开地址。

保存新地址时，App 必须清除旧服务器的 Access Token 和 Refresh Token，并重新创建 ApiClient、认证控制器和所有 Repository。考试目标、计划、欠债、可信观看、答题、报表和 AI 数据仍全部来自当前服务端，不在客户端持久化业务副本。

## 后果（Consequences）

- 模拟器、物理 iPhone 和自建环境可以在不重新构建 App 的情况下切换服务端。
- 切换服务器会退出当前账号，防止旧 Token 被发送到新服务器。
- App 启动依赖图需要支持按服务器配置整体重建。
- HTTP 只用于本机或局域网开发，生产环境仍要求 HTTPS。
- 必须测试地址规范化、健康检查、失败回滚和 Token 清除。

## 被否决的方案（Rejected Alternatives）

- 本地 Mock 全部接口：无法验证真实服务端状态机，并偏离业务真相在服务端的原则。
- 仅修改 Dio `baseUrl`：播放器和其他对象可能保留旧基础地址，容易产生部分切换。
- 保存后要求手动重启：实现简单，但用户无法确认何时真正切换完成。
- 保存多个环境列表：超出当前单地址切换需求，增加无必要的配置管理。
