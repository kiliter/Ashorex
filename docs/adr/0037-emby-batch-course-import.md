# ADR-0037：绑定媒体库后的课程发现与批量导入

- 状态：已接受（2026-09-08 用户确认）
- 关联：ADR-0027、ADR-0033；补齐 T06 / T19

## 背景

现有保存媒体库只写配置，课程新增仍要求手填 Item ID；已绑定库的课程发现没有接到导入界面。用户已批准直接展示候选课程、批量选择后导入的闭环。

## 决策

1. Emby 同步页的媒体库绑定区只放「导入课程」按钮，点击后打开选课弹窗；课程库的导入入口复用同一个弹窗。保存绑定只保存配置，不展开课程列表。弹窗打开时加载最新已保存绑定范围，搜索、多选、导入进度、结果与重试均留在弹窗内，内容独立滚动、关闭按钮固定可见；导入期间禁止关闭。
2. 无需输入关键词，分页读取全部已绑定视频库的 Series / Movie，按绑定的剧集、电影、混合类型限制，书籍库不参与。按名称和 ID 排序去重；界面本地搜索、分页、多选、全选筛选结果中的未导入课程。封面走认证后台代理，课时数仅对当前页按需读取，未知或失败不伪装为零。
3. 浏览不写课程；只有「导入所选」才提交。客户端逐门串行请求服务端，显示进度及逐项成功、已存在、失败结果；单门失败不阻断其他课程，网络响应丢失后可重试。
4. 服务端逐次通过当前绑定媒体库的用户作用域查询验证来源与类型匹配，不沿物理父链校验媒体库归属（媒体库视图与物理父节点不一定一致），远端完整元数据与课时读取在写事务外完成，短事务内创建课程与全部课时。任一页失败不留下空壳或部分快照。
5. 相同来源重复提交幂等返回原课程，归档课程显示「已归档」且不可选，不通过导入自动恢复；由归档区显式恢复。唯一索引继续兜底并发重复，不改数据库。
6. 已导入课程后续用课程库「同步 / 同步全部」更新，发现新课程仍需选择，不自动导入整个媒体库。
7. 后台 DTO 不包含 Emby 主机、密钥、原始路径；封面使用固定路径、用户作用域存在性校验、大小与类型限制。内部 API 记录在本 ADR，按 ADR-0033 不纳入 App OpenAPI。

## 内部接口

- GET `/admin/api/emby-import/candidates`：全部候选（id、name、itemType、hasPrimaryImage、courseId、status）。status 为 NEW / ACTIVE / ARCHIVED。
- GET `/admin/api/emby-import/details?sourceId=...`：当前候选的准确 resourceCount，仅按需加载。
- GET `/admin/api/emby-import/cover?sourceId=...`：认证封面，缺失返回 404；最多 2 MiB，仅 JPEG / PNG / WebP。
- POST `/admin/api/emby-import`：`{sourceId}`；返回 courseId、title、status（IMPORTED / EXISTS / ARCHIVED）。失败为稳定 Problem Details。

## 验收

无需关键词即展示绑定范围；搜索和跨页选择正确；全选不包含已导入或归档；逐项结果与失败重试；重复与并发导入不重复；书籍/未绑定来源拒绝；分页失败不写入；网络请求不占写事务；封面无凭据与路径泄露；编译与窄测试通过，真实启动健康为 UP。

- 管理后台 `npm run build` 通过（包含 vue-tsc），服务端 Java 21 编译通过。
- `CourseImportServiceTest` 9 项、`EmbyClientContractTest` 12 项、`CatalogAdminControllerTest` 3 项全部通过，无数据库测试。
- 根目录 `make format` 通过；`git diff --check` 通过。
- 通过 `./run.sh server` 在独立临时目录真实启动，健康端点为 UP；假 Emby 的 3 门课程无需关键词即可发现，逐门导入后课时数一致，重复提交保持课程及课时 ID，不产生重复行。移除绑定后返回稳定范围错误，未登录访问返回 401。
- 未连接用户真实 Emby；未运行 GitHub CI 全量验证，实际媒体库与页面交互仍需在更新后的服务中验收。

### 详情类型误判修复

课时计数、封面与导入统一复用绑定库候选查询判定归属，不对中间父节点调用课程类型校验。回归覆盖候选来自绑定库但物理父节点不可建课、未绑定来源拒绝与解绑后拒绝。
