# ADR-0040：当前 App 页面与活动快照

- 状态：提议，待人工批准；批准前不实现。
- 日期：2026-09-08
- 关联：ADR-0026、ADR-0028；T12、T17、T30、T31。

## 范围差异

现有 Spec §5.5、§7.2 只规定前后台、版本与心跳时间，未定义当前页面和活动。新增当前活动属于范围扩展。

## 最小变更提案

- 心跳增加白名单页面标识、活动状态与可选 Todo ID。页面覆盖首页、学习、课程详情、视频、专注、数据、我的、待办详情和催办；未知页面显示“其他页面”，不上传原始路由参数。
- 区分浏览页面、视频加载/播放/暂停/缓冲、专注进行/暂停和回应催办；进入视频页不等于正在播放，进入专注页不等于正在计时。
- 定时心跳继续保留；页面、活动及前后台变化时合并补发最新快照，请求串行，失败后只补最新状态，避免旧请求覆盖新状态。
- 服务端只维护 user_presence 单行快照，以接收时间记录更新时间；新增追加迁移，兼容旧客户端显示“未知”。Todo ID 校验当前用户归属；展示名称由服务端读取。
- 后台“在线与进度”、督学端学员总览/详情展示中文页面、活动、任务名称与更新时间。督学端遵循原有绑定与 can_view 权限。
- 前后台状态与专注计时分别呈现，例如“App 已切后台；专注计时中”，不能据此推断用户实际在学习。离线后标注“最后上报”，不得继续显示为实时活动。
- 仅展示本 App 自报状态，不识别其他 App，不保存页面轨迹，也不作为可信学习证明。
- 页面停留与心跳不刷新有效操作时间，不改变催办阈值、学习时长和完成判定。

## 批准后的实施与验收

1. 同步 OpenAPI 与原型展示；扩展服务端 DTO、单行持久化及后台/督学查询。
2. 接入 Flutter 路由、播放器、专注和生命周期状态，再接入后台与督学显示。
3. 窄测试覆盖旧客户端、非法状态、归属权限、切页、播放暂停/缓冲、专注暂停、切后台、离线、请求顺序和有效操作时间不变。
4. 迁移 clean 后真实启动，健康端点 UP；真实设备验证页面与播放状态；全量验证交 GitHub CI。
