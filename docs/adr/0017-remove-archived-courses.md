# ADR-0017：从已归档课程区域单个或批量移除课程

- 状态：已接受（2026-09-02 人工批准）
- 日期：2026-09-02
- 补充：ADR-0016

## 背景（Context）

ADR-0016 将后台“删除课程”定义为可恢复归档，确保误操作不会破坏课时、可信进度、作战单、欠债、题目和学习内容。但随着归档课程增多，管理员还需要从“已归档课程”区域清理不再维护的课程，并要求支持单个删除、批量删除和二次确认。

直接物理删除课程及其关联记录会破坏可信学习历史，也可能因计划、欠债、观看会话和答题记录的外键关系造成部分删除。因此，本 ADR 将“删除归档课程”定义为不可从后台恢复的管理端移除，而不是物理擦除学习数据。

## 决策（Decision）

### 课程生命周期

后台课程使用以下生命周期：

```text
活动课程 → 已归档课程 → 已移除课程
              ↘ 恢复为活动课程
```

- 活动课程继续使用 `enabled=true`。
- 已归档课程使用 `enabled=false` 且 `removed_at` 为空，可在后台恢复。
- 已移除课程使用 `enabled=false` 且记录 UTC `removed_at`，不再出现在活动课程、已归档课程、App 目录、计划选择或定时同步中。
- 已移除课程的课程行、课时、可信进度、计划、欠债、题目、全文、摘要、内容任务及审计记录不得物理删除。
- 管理员以后重新添加相同 Emby 来源时，服务端恢复原课程身份并清除 `removed_at`，继续复用原课程 ID、课时 ID 和学习历史；执行结果必须明确显示“恢复历史课程”。

### 单个与批量删除

- “已归档课程”区域提供逐行勾选、全选当前列表、“删除所选”和单个“删除”操作。
- 单次最多删除 50 门课程；服务端拒绝不存在或仍处于活动状态的课程 ID，已经移除的课程按幂等请求跳过。
- 单个和批量操作都必须先显示二次确认弹窗，列出课程数量、课时总数，并明确提示“移除后不能从后台手工恢复，但学习历史仍会保留”。
- 确认按钮使用明确动词“确认删除”，默认焦点不得落在危险按钮；取消、关闭和 Escape 均不得提交。
- 批量删除在一个短事务中完成整批校验和状态更新；任一课程不存在或仍为活动状态时整批不写入。
- 重复提交同一批已成功移除的课程视为幂等成功，不重复产生审计记录。
- 删除操作记录管理员、课程 ID、发生时间和请求 ID，不记录 Emby 路径、密钥或课程内容。

### 接口边界

本变更只增加内部 ADMIN 表单操作和数据库迁移，不新增或修改 `/api/v1` 学习端契约。控制器只调用应用服务，事务、状态校验和审计由应用服务负责。

## 后果（Consequences）

- 管理员可以清理已归档课程区域，并通过批量操作降低重复维护成本。
- 二次确认和整批事务可降低误删及部分成功造成的困惑。
- 已移除课程不能在后台直接恢复，但重新添加相同 Emby 来源时仍能无缝复用历史身份。
- 数据库仍保留可信学习和审计数据，因此该操作不会减少数据库历史数据体积；真正的数据保留期限与物理清理不属于 V1。

## 被否决的方案（Rejected Alternatives）

- 级联物理删除课程和全部关联记录：会破坏可信学习数据、计划、欠债和审计链路。
- 仅由前端隐藏课程：换浏览器或直接提交请求后状态不一致，不能作为业务真相。
- 批量操作逐门提交：中途失败会产生难以解释的部分删除结果。
- 删除后永远禁止相同来源重新添加：会阻断管理员重新启用课程，也违背媒体来源重建后的历史连续性要求。
