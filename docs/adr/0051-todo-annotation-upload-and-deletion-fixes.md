# ADR-0051：回填、上传重试、专注完成与删除日期缺陷修复

- 状态：已接受（2026-09-10 用户确认修复）
- 关联：Spec §6.2 / §7.3 / §7.4、R08 / R11 / R19、T09 / T10 / T11 / T26、ADR-0036

## 问题与决策

1. 已完成 Todo 再调用 `complete` 会幂等返回而不写入新备注。已完成项和播放器、专注页的备注/附件入口统一调用既有 `annotate`；仅回填显示「保存」，不因缺少完成凭证而阻止记录。真正手动完成仍走 `complete`，保持凭证校验。播放器补报已触发自动完成时，同样只保存回填。
2. 附件上传收到 401 后，现有鉴权流程刷新成功再重试时，对已发送的 `FormData` 调用 `clone()`，重建表单及文件流。普通 JSON 请求、重试次数和跨会话校验不变。
3. 专注自然结束先暂停落账；缺凭证时面板仅上传附件并调用 `annotate`，凭证齐全后才能保存。保存成功返回运行页继续调用 `focus/finish`，得到 `DONE + FINISHED`。取消或保存失败不执行完成，不累计等待凭证时间。手动提前完成仍保持 `complete` 的停止语义，不改变 `STOPPED` 含义或统计规则。
4. 当天删除规则及日视图删除数量按实际 `deleted_at` 归集。应用层通过 `UserTimeService` 计算 `[本地日开始, 次日本地日开始)`；删除流程复用写台账的同一时间点，避免跨午夜漂移，支持夏令时。台账 `local_date` 继续保存原计划日期。规则开关、阈值和督学人条件保持原样。

## 兼容性与发布

- 不新增或修改公开 API、请求/响应字段、枚举、错误码、状态机和数据库结构；无需迁移，OpenAPI 合同不变。
- 新 App 复用已发布的 `annotate`、`complete`、`focus/finish` 和鉴权接口，可与原服务端配合使用。前三项客户端修复需要用户升级 App 后生效；旧 App 在新服务端继续按原接口运行，但仍保留原有客户端缺陷，不伪造兼容成功。
- 第四项升级服务端即可生效，旧 App 可直接使用校正后的删除数量。App 与服务端可独立发布及回退，回退服务端会恢复旧删除日期口径；不改写历史 `DONE + STOPPED` 数据，也不追补过去未产生的提醒。
