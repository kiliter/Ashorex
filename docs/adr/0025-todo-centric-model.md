# ADR-0025：以 Todo 中心模型取代作战单、可信播放、学习欠债与答题体系

- 状态：提议（待人工批准）
- 日期：2026-09-07
- 相关：取代 ADR-0011、ADR-0013、ADR-0019、ADR-0024；作废 ADR-0004 / ADR-0007 / ADR-0008 涉及的学习内容生产链路

## 背景

V1 用一条重工闭环表达学习监督：考试目标 → 作战单（整单快照 + 版本号）→ 可信视频学习（服务端裁决可信最大位置、播放票据、心跳序号、进度验活、按钮授权快进）→ 必答题 → 模拟考试 → 日终结算 → 学习欠债 → 日报 / 周报 / 晚间审判。

实际使用中暴露三个问题：

1. **可信播放的成本与收益不匹配**。播放票据、位置跳跃拒绝、验活弹窗、三次心跳暂停等机制带来大量状态与失败分支，但监督效果取决于「有没有人盯」，而不是「进度能不能被伪造」。
2. **欠债与答题体系把简单的事复杂化**。用户真正需要的是「今天这几件事做完没做完」，而 `VIDEO_WATCH / QUIZ / FOCUS` 三类债务、还债计划、豁免流程构成了独立子系统。
3. **作战单的整单快照 + 不可改限制**与真实使用冲突。计划会临时变，用户需要随时增删改。

用户明确要求重构为 todo list 风格，并允许任意更改历史需求。

## 决策

引入单一任务实体 `Todo`，取代作战单、计划项、欠债、答题与模拟考试：

- Todo 只有三种类型：`COURSE`（课程）、`FOCUS`（专注计时）、`TASK`（待办事项）。三类共用一张 `todos` 表，类型专属列可空。
- 课程 Todo 支持**目标进度**（千分比），达到即判定完成，用于「长视频只需看 30%」的场景。
- 状态机简化为 `TODO → IN_PROGRESS → DONE`，没有 `ABANDONED`、`CLOSED_WITH_DEBT`，没有日终自动终态。
- 播放改为普通播放器：进度条可自由拖动，支持快退 / 快进 10 秒、倍速 0.75–2.0、全屏。服务端只接收 `positionMs`（取 max，单调不回退）与 `deltaWatchedMs`（真实经过时间）。
- 删除播放票据 HMAC、可信最大位置裁决、位置跳跃拒绝、进度验活、三次心跳暂停、按钮授权快进。
- 删除欠债域（`learning_debts`、`debt_repayments`、豁免）、答题域（`questions`、`quiz_*`、题目草稿与发布）、模拟考试域（`mock_exam_*`）、日终结算与日报周报晚间审判、AI 内容生产链路（ASR / LLM / OpenRouter / 全文 / 摘要）、视觉伴学「毛线团团」。
- 未完成的历史 Todo 不产生任何债务对象，只由「未完成汇总」视图跨日期聚合，支持顺延、补记完成（必填备注）、删除（必填原因）。
- 监督压力由「服务端扫描 + 催办 + 督学人」承担（见 ADR-0026、ADR-0028），不再由播放校验承担。

## 后果

正面：

- 领域模型从 7 个子域收敛到 1 个核心实体 + 3 个支撑域（catalog、nag、supervision）。
- 客户端播放器回归标准实现，去掉全部授权与拒绝分支，真机稳定性与可维护性提升。
- 用户可随时增删改当日任务，符合真实使用节奏。

负面与代价：

- 进度可被人为拖动，学习数据不再具备防伪属性。这是自觉接受的取舍：V2 的可信度来自督学人与催办留痕，而不是播放校验。
- V1 的欠债、答题、模拟考试与报表数据不再有承载结构，需要数据库重建（见 ADR-0031）。
- 大量既有服务端与 Flutter 代码需要删除，短期改动面很大。

## 替代方案

1. **保留可信播放，只重做首页 UI**。否决：用户要求移除可信播放，且不解决欠债与答题的复杂度。
2. **保留欠债但简化为一个计数**。否决：与「未完成汇总」视图重复，且仍需状态机与结算入口。
3. **保留答题作为可选能力**。否决：题库、草稿、审核、发布链路的维护成本远高于其在监督闭环里的价值。
