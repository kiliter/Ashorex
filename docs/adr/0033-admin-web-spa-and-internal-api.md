# ADR-0033：内部管理后台改为 Vue 3 SPA 与 /admin/api 内部接口

- 状态：已接受
- 日期：2026-09-08
- 取代：ADR-0006 中「后台以 Thymeleaf 表单页面呈现」的实现约定（该 ADR 关于「运行配置存库、密钥不出服务端」的决策继续有效）

## 背景

V2 冻结文档原本规定内部管理后台使用 Thymeleaf 表单页面，并明确「不暴露 REST API」。
实施过程中后台承担的交互超出表单提交的表达能力：

- 归档区的彻底删除必须先展示级联清单、再输入实体名称确认，属于同页多步状态机；
- Emby 同步页需要联想搜索来源、预览映射方案、逐项确认歧义映射；
- 在线与进度、催办记录需要 30 秒轮询刷新与客户端筛选分档；
- 运行配置需要「测试连接」这类不改变数据、只回报探测结果的交互。

用整页提交 + 重定向实现上述交互会产生大量中间态页面与隐藏表单字段，且每次刷新都要重算全量视图。

## 决策

1. 内部管理后台改为 Vue 3 SPA，源码位于 `apps/admin-web`，构建产物输出到服务端静态资源目录，由同一个 Spring Boot 进程在 `/admin` 下提供。
2. 新增一组内部 REST 接口，前缀 `/admin/api/**`，只服务后台自身。
3. 该组接口**不纳入** `docs/api/openapi.yaml`。`openapi.yaml` 的契约范围仅限 App 客户端使用的 `/api/v1/**`。
4. 该组接口的认证沿用管理员 HttpOnly Session Cookie + CSRF，与 App 的 Bearer 令牌体系完全隔离；不下发任何密钥给浏览器。
5. 后台接口一律返回 RFC 9457 Problem Details 与稳定 `errorCode`，与 `/api/v1` 保持同一套错误约定。

## 理由

- 后台与 App 的消费者、认证方式、变更节奏都不同，混入同一份对外契约会让 App 契约被后台改动频繁污染。
- 后台是内部工具，只有管理员可达，规模仍是「少于 5 人同时在线」，SPA 带来的复杂度局限在一个前端目录内。
- 保持单进程、单部署单元，不引入独立前端服务、Node 运行时或反向代理规则。

## 影响

- `apps/admin-web` 的构建通过 `frontend-maven-plugin` 挂在服务端打包生命周期上；`-Dskip.admin.web=true` 可跳过，便于纯后端迭代。
- 后台接口没有 OpenAPI 契约测试兜底，因此**后台的行为约束必须由 Controller 切片测试覆盖**。
- 学习端仍然只能访问 `/api/v1/**`；任何把 `/admin/api` 暴露给 App 的做法都视为违规。
- 安全边界不变：密钥只回传「是否已配置」布尔值；页面与后台 API 响应都不得包含文件系统绝对路径、Emby 原始路径或堆栈信息。

## 备选方案

- **保持 Thymeleaf**：交互复杂度需要靠隐藏字段与多次重定向硬撑，级联删除确认与映射预览尤其笨重，已否决。
- **Thymeleaf 页面 + 少量 AJAX 端点**：等于同时维护两套渲染路径与两套状态来源，收益不如直接分层，已否决。
- **独立部署前端**：违反 V2 的单实例、单部署单元约束，已否决。
