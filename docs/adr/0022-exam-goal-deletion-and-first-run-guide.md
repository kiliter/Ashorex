# ADR-0022：考试目标可在客户端删除，首次引导以 pop 返回首页

- 状态：已接受
- 日期：2026-09-04

## 背景

ADR-0020 允许同一用户保存多个考试目标后，客户端只有新增和修改入口，没有删除入口。用户误建、重复建或考试作废后无法清理，首页考试卡片会一直堆积。

同时首次登录引导存在缺陷：首页在 `exams` 为空时用 `context.push('/exam-goal')` 打开考试目标页，而该页保存成功后执行 `context.go('/home')`。`go` 会替换路由栈，不会触发 `AppShell` 的 `didPopNext`，因此首页不会重新读取快照，仍持有空考试列表，随即再次压入考试目标页。用户表现为"添加完考试后卡在页面里出不去"，并且每次点击保存都会新建一条考试目标，从而在考试列表里堆出多条重复记录。

## 决策

考试目标支持用户删除：

- 新增 `DELETE /api/v1/exam-goals/{goalId}`，成功返回 204，目标不存在或不属于当前用户返回 404 与稳定错误码 `EXAM_GOAL_NOT_FOUND`。
- 删除只清除 `exam_goals` 行与 `exam_goal_courses` 绑定。可信观看进度、作战单、学习欠债、答题记录和报表都不属于考试目标，删除后全部保留。
- 允许删除最后一个考试目标；此时首页回到考试目标设置引导。
- 客户端在「我的 → 考试设置」每场考试右侧提供删除按钮，删除前必须二次确认，确认文案明确说明学习记录不会被删除。
- 删除仍由服务端校验归属，客户端不做业务判断。

首次引导的返回方式固定为 pop：

- 考试目标页保存成功后，只要路由栈可回退就执行 `pop`，让 `AppShell.didPopNext` 触发首页重新读取；栈不可回退时才回退到 `go('/home')`。
- 首页在没有考试目标时只自动引导一次。引导页返回后重新读取快照；若仍没有考试目标，改为展示空态和显式「设置考试目标」按钮，不再自动跳转。

## 后果

- 用户可以自行清理误建和作废的考试目标，不需要管理员介入。
- 删除语义被限定为"取消进度计算目标"，不是"清除学习历史"，与学习数据可信、可审计的优先级一致。
- 首页与考试目标页之间不再出现自动跳转循环，重复保存导致的重复考试目标不会再产生。
- 首页空态多了一个显式入口，用户在没有考试目标时仍可主动进入设置。

## 被否决的方案

- 只在管理后台提供删除：考试目标是用户自己的学习目标，后台代删既不及时也不符合归属边界。
- 删除考试目标时连带删除相关学习记录与欠债：可信学习数据必须保留，删除目标不应销毁已发生的学习事实。
- 首页保留自动跳转但加计数上限：仍会出现多次弹栈，用户体验上依然是被"困住"，不如一次引导加显式入口清晰。
- 通过在首页保存后调用 `bumpHomeRefresh()` 修补 `go('/home')`：绕过了既有的 `didPopNext` 刷新链路，两套刷新机制并存更难维护。
