# ADR-0003：使用 Emby 提供媒体能力

- 状态：已接受
- 日期：2026-08-27

## 背景（Context）

上岸需要播放已有课程视频，但 V1 不应自行建设媒体库、视频转码和多码率 HLS 系统。Emby 已能提供媒体目录、元数据、直放与转码能力，但 Emby 播放进度不能证明用户真实完成学习。

## 决策（Decision）

Emby 负责视频库、剧集、媒体信息、封面、直放与 HLS 转码；上岸服务端保存课程快照、业务关联和可信学习进度。管理员将固定的 Emby Series 或 Folder 绑定为课程，服务端定时或手动同步媒体项。

V1 媒体全部通过上岸服务端代理。服务端只连接配置中的固定 Emby 主机，使用短期 HMAC 播放票据保护代理路由，流式转发 Range 与 HLS 内容，不把完整视频或分片缓冲到内存。Emby API Key 永远不进入客户端、日志或 API 响应。

## 后果（Consequences）

- V1 可以复用成熟媒体管理和转码能力，聚焦学习监督规则。
- 上岸必须维护独立的可信观看会话、心跳、验活和完成阈值。
- 媒体代理增加服务端带宽，但少于 5 人并发时可接受。
- Emby 短暂不可用时，本地课程快照仍可用于展示历史和计划数据。
- 代理实现必须严格防止 SSRF、路径穿越和密钥泄露。

## 被否决的方案（Rejected Alternatives）

- 客户端直接携带 Emby API Key：会泄露服务端凭据，无法接受。
- 直接使用 Emby 播放进度作为学习进度：无法满足可信观看规则。
- 上岸服务端自行转码视频：重复建设媒体能力并显著增加运维成本。
- V1 离线下载：扩大存储、授权、进度同步与安全范围。
