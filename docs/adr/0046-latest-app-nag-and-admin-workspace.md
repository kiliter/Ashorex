# ADR-0046：App 最新催办与后台可视区域布局

- 状态：已接受（2026-09-09 用户批准催办规则调整并要求优化四个后台页面）
- 关联：T13 / T18 / T19 / T20 / T30，原型 7-1 / 8-3 / 8-4 / 8-5 / 运行配置

## 决策

1. 替代 ADR-0026 的逐条弹窗规则。App 同一用户同一本地日期只要求回应最新成功投递的催办，按创建时间及 ID 稳定排序；较早的未回应记录标记 appSuperseded，保留触发、状态、渠道和尝试历史，不冒充已回应。最新记录回应后，旧记录不再弹出。
2. 标记仅影响 App 待回应查询与待回应数量，不影响 Bark / Server 酱原有逐条通知、全屏超时降级、失败重投或每日次数。失败尚未送达的记录不替代已送达提醒；旧失败记录晚到成功也不得重新抢占新提醒。追加迁移，回填存量，禁止修改已发布迁移。
3. 旧版 App 兼容：已被替代的旧弹框提交仍返回 200 和原记录真实状态，不写入虚假回应、不刷新有效操作；旧客户端按既有成功关页流程补查最新催办。新增 appSuperseded 为可选响应字段，旧版本可忽略；不要求升级 App，不新增旧版无法识别的阻断错误码。失败与重连继续通过心跳、SSE 和数据库查询兜底。
4. 延续 ADR-0045 全失败 PENDING 的后台取消与原记录重投。最后一次失败为 Bark 且个人 Bark 仍启用时，重投仍使用 Bark，避免学员上线后意外变成全屏；个人关闭 Bark 后恢复当前渠道策略。失败仍可刷新后重试，不添加无限自动重试。
5. 催办策略分为全局默认、通知方式、用户覆盖；全局表单操作固定在底部。运行配置按 Emby、Server 酱、系统 Bark、功能开关切换，切换保留输入，底部统一保存本页全部配置。
6. 催办记录使用固定标题、页签与筛选，状态分布默认收起，流水占据剩余高度且表头固定。Emby 同步分媒体库绑定、映射与失联、重新绑定，操作区固定、内容独立滚动。右侧工作区限定浏览器高度，导航独立滚动，不再用整页长滚动寻找操作。窄屏控件换行、内容可滚动且无页面横向溢出。
7. 沿用系统字体、现有浅色令牌和控件，不修改后台接口权限、字段保存和外部通知语义；同步唯一 UI 原型。

## 验收

- 无数据库窄测试：替代标记影响 App 待回应、旧弹框兼容成功关闭且不伪造回应、投递后合并、Bark 失败后重投仍走 Bark、既有重放与渠道隔离。
- 独立临时数据库真实启动并验证迁移、存量合并、回应后无旧记录、迟到成功与 Bark 流水保留；健康端点 UP。
- 沿用既有 Flutter 催办流程、后台类型检查与构建；浏览器检查四页常用桌面尺寸和窄屏下的滚动与固定操作。全量验证仅交 GitHub CI。

- 服务端 43 项窄测试通过：NagManagementServiceTest、NagResponseServiceTest、NagDeliveryServiceTest；不连接数据库。覆盖个人 Bark 开关与重投渠道、旧版弹框兼容、替代标记不阻断 Bark、失败不合并 App 提醒。
- 独立 V008 临时库植入多条同日催办及 Bark 流水后真实升级 V009，健康 UP，外键检查无异常、完整性 ok。旧版用户名密码与原因请求直接可用；最新回应后 pending 返回 204；旧失败项重投成功后仍不弹出；其他用户记录不受影响。

- OpenAPI 运行时结构比对通过，47 个 App 操作一致，新增响应字段保持可选。
- 未替换业务服务或发送真实 Bark 通知；设备接收、GitHub CI 全量验证与发布仍待执行。
