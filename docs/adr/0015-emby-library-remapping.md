# ADR-0015：Emby 媒体库同步与稳定课时映射

- 状态：已接受
- 日期：2026-09-02
- 补充：ADR-0003

## 背景（Context）

ADR-0003 规定管理员将 Emby Series 或 Folder 绑定为课程，并由上岸保存本地课时快照。现有实现把 `emby_item_id` 当作外部课时唯一身份；当管理员删除 Emby 媒体库后以相同文件重新创建媒体库时，父节点 ID 和视频 Item ID 都可能变化。若按新 Item ID 插入新课时，原课时关联的可信进度、作战单、欠债、题目、全文、摘要和内容任务将与新视频断开；若仅按标题强制合并，同名视频又可能被错误映射。

管理后台还只能手工填写父节点 ID，且同步只读取 `Episode` 和普通 `Video`，不能完整覆盖包含 `Movie`、`Episode` 和 `Video` 的混合媒体库。当前同步使用全局 `/Items`，也没有按配置的 Emby 用户限定可见范围和分页读取大媒体库。

## 决策（Decision）

管理后台允许从当前 Emby 用户可见的媒体库列表中选择媒体库创建课程或重新绑定已有课程，同时保留手工绑定 Series/Folder ID 的高级入口。媒体库列表和课时查询只使用固定 Emby 配置，不接受请求级 Base URL 或 API Key。

课时同步使用配置的 `EMBY_USER_ID` 调用用户作用域 Items API，递归、分页读取 `Movie`、`Episode` 和 `Video`，同时要求 `MediaType=Video` 且不是 Folder。每页结果完整取得后再进入本地短事务；任一页失败时不写入部分快照。结果按 Emby Item ID 去重，并形成稳定的课程内顺序。

`media_items.id` 继续作为上岸内部不可变课时身份。`emby_item_id` 改为当前播放源标识，可以在确认是同一物理媒体后原位更新。同步从 Emby `Path` 计算带版本前缀的 SHA-256 来源指纹，只保存指纹，不保存或展示原始媒体路径。

重新绑定或同步时按以下优先级匹配：

1. 当前 Emby Item ID 完全相同。
2. 非空来源指纹在课程内一一匹配。
3. 仅对尚无来源指纹的历史课时，标题规范化后完全一致、时长差不超过 2 秒，且新旧候选在课程内均唯一时，执行一次兼容映射。
4. 其余情况视为新课时；若一个新课时可能对应多个旧课时，或一个旧课时可能对应多个新课时，则标记为映射冲突。

自动或人工确认映射只更新原 `media_items` 行的当前 Emby Item ID、来源指纹和远端元数据，不修改本地 ID、启用状态、管理员排序或任何业务外键。每次 Item ID 变化写入不含路径的映射审计记录。

重新绑定先读取并校验新媒体库的完整快照，再在一个短事务中完成课程父节点更新、课时映射和快照应用。存在映射冲突时不更新课程绑定、不写入部分映射，管理员必须在后台明确选择对应关系后重试。普通同步发现父节点不存在或无权访问时返回稳定错误并保留最后一次可用本地快照；只有父节点仍存在且其完整结果确实为空时，才允许把原课时标记为不可用。

## 后果（Consequences）

- 删除并重建同一路径的 Emby 媒体库后，可通过重新选择媒体库恢复播放源，同时保留上岸内部课时及其全部业务历史。
- 当前已经失去旧 Emby 节点、且尚未保存来源指纹的课时，只能使用严格的一次性历史元数据匹配；歧义数据必须人工确认。
- 数据库需要追加来源指纹、媒体类型和映射审计结构，但不修改已发布迁移。
- ZIP 导入继续使用当前 Emby Item ID 校验；已经导入到本地课时的全文和摘要会随本地课时身份保留，不因外部 Item ID 更新而丢失。
- 原始 Emby 路径不得进入数据库、页面、日志、错误响应或业务 API；路径只在单次响应内用于计算指纹。
- 大媒体库同步增加分页请求次数，但避免一次加载数千条数据和部分结果写入。

## 被否决的方案（Rejected Alternatives）

- 继续把 Emby Item ID 当作永久课时身份：媒体库重建后会割裂全部学习历史。
- 只按标题自动合并：同名课时普遍存在，可能把可信进度和题目关联到错误视频。
- 保存原始媒体路径：虽然便于诊断，但会扩大服务器目录信息的泄露范围。
- 删除旧课时并批量迁移所有业务外键：涉及大量历史表，风险高于原位更新外部标识。
- 父节点查询为空时直接标记全部不可用：无法区分合法空媒体库与已经删除的父节点。
