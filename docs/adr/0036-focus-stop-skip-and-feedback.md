# ADR-0036：专注停止、跳过留痕与轻提示

- 状态：已接受（用户于 2026-09-08 明确批准并修订）
- 日期：2026-09-08
- 关联：ADR-0025、Spec §6.2 / §17 A7、T09 / T26 / T32

## 冲突与问题

现行规范把提前结束定义为不可恢复的 `ABANDONED`，原型 3-2 把放弃作为与暂停并排的红色主按钮。新要求改为开始、暂停、继续、停止，并将跳过移到次要位置，二次确认且写库留痕。

当前专注页按 `_running` 与已累计时长推导按钮和状态，导致已结束的数据被显示为暂停并提交继续请求；页面应以服务端返回的完整状态为依据。

## 决策

| 操作 | 行为与数据口径 |
|---|---|
| 开始 | 从准备开始或已停止进入运行；已停止后再次开始开启新一轮，本轮时长从零开始、倒计时恢复设定时长 |
| 暂停 / 继续 | 暂停不计时，继续从剩余时间运行 |
| 停止 | 结束本段计时并保存实际时长，标记已停止；未达目标不算完成，可再次开始 |
| 跳过 | 二次确认后标记 `ABANDONED`（界面称为已跳过），保留时长，Todo 仍未完成；不显示继续按钮，不自动算完成或删除 |
| 自然结束 | 达到目标后按现有凭证规则完成；缺少凭证时不误显示运行，也不虚增时长 |

状态为 `IDLE / RUNNING / PAUSED / STOPPED / ABANDONED / FINISHED`。跳过允许从未开始、运行、暂停、已停止发起。停止和跳过均明确说明结果；二次确认取消不提交请求。已完成及已跳过不得继续计时。离页与回前台重新对齐服务端状态。

## 留痕与迁移

- 服务端在同一短事务内更新状态并保存专注操作事件：用户、Todo、操作、前后状态、服务端时间、本段时长、累计时长及请求幂等标识。
- 开始、暂停、继续、停止、跳过、完成均可追踪；重复请求不重复累计时长或写事件。统计继续按真实累计时长计算，不把跳过计为完成。本次不增加新的统计页面。
- 新增下一编号 Flyway 迁移，不修改已发布 baseline；历史 `ABANDONED` 不迁移、不改写，保留原时长与未完成状态。历史事件缺失不伪造，迁移来源明确标记。
- 操作记录纳入既有 Todo / 用户删除级联和孤儿检查；OpenAPI 与客户端枚举同步更新。

## 交互草案

- 沿用浅色背景、系统字体、深蓝正文和环形倒计时。
- 底部主要操作区展示「开始」，或「暂停 / 继续」与描边「停止」。
- 「跳过」移到右上角低强调文字入口，与底部计时按钮分离，点击区域至少 44pt。
- 跳过确认使用圆角底部面板：标题「跳过这次专注？」；正文「已专注的时间会保留，这项待办仍记为未完成。」；按钮「返回专注」「确认跳过」。默认不强调确认按钮。
- 普通成功和失败提示统一采用右上角安全区内浮动圆角轻提示：浅底、语义图标、简短中文、轻阴影、自动消失；错误适当延长显示并可关闭，支持读屏，不遮挡底部主要按钮。
- 状态冲突显示「专注状态已更新，已刷新当前页面」，同时重新查询；不向用户直接展示枚举名、异常对象或技术堆栈。
- 删除、跳过等确认面板以及强制回应的全屏催办仍保留明确确认流程，不替换成自动消失提示。

## 验收

1. 开始、暂停、继续、停止、再次开始、跳过与自然结束的状态及累计时间正确。
2. 跳过取消不写库；确认只写一次；重复点击、重试不重复计时。
3. 历史结束记录进入页面不再显示暂停或发送继续请求。
4. 切后台、回前台、离页重入均对齐服务端；凭证取消与缺失不造成计时漂移。
5. 服务端状态与幂等窄测试、Flutter 状态按钮与确认面板及提示窄测试通过；迁移后真实启动健康检查 UP。
6. 同步原型 2-3 / 3-2、Spec §6.2 / A7、实施计划、追踪矩阵、OpenAPI 与 AGENTS 状态说明；模拟器检查布局与读屏语义，完整验证交由 CI。

## 用户补充的计时与统计口径

- 暂停 / 继续属于同一轮；停止后再次开始是全新一轮，不能拼接多段已停止记录来达标。
- `focusedMs` 保存所有轮次实际时长；`focusAttemptBaseMs` 为本轮开始时的历史累计基线，本轮时长为两者差值加运行段。
- 完成判定只看本轮达到设定时长，历史未完成时长不能抵扣。界面仅展示完成 / 未完成、本轮时长、剩余时间，不显示专注完成百分比；圆环仅表示本轮剩余倒计时。
- 操作留痕复用 `todo_progress_events`，新增专注操作、前后状态、累计时长和幂等标识列，沿用既有级联；无独立统计页。
