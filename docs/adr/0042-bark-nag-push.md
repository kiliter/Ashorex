# ADR-0042：Bark 催办渠道与 App 打开链接

- 状态：已批准（2026-09-08，Bark 启用后替代 Server 酱）
- 日期：2026-09-08
- 关联：ADR-0026、ADR-0041

## 最小变更

- 新增 BARK 渠道。每个用户在 App 设置填写自己的 Bark 服务地址与设备 Key，提供个人独立开关；默认未配置/关闭，不改变现有投递。
- 该用户启用后，离线或全屏超时阶段改用 Bark，替代 Server 酱，不并发双发；Bark 失败记录失败，不自动向 Server 酱重发。手动催办可以明确指定 Bark。
- Bark 请求固定包含 `group=上岸`、`level=critical`（Bark 的“重要通知”）、`url=shangan://home`，对应用户要求的分组、重要通知、点击打开软件三项。自动催办原文保持不变；手动催办使用 ADR-0041 标题与说明。
- 为 App 注册 shangan URL Scheme；点击仅打开 App，会话和用户权限仍走原认证流程；学员回前台后按原逻辑补查自己的待回应催办，不通过 URL 传 Token 或任意目标用户。
- 新增配置与渠道约束迁移；超时、免打扰、降级去重和脱敏沿用现有要求。Bark Key 不回显，空值保留已保存值，日志和错误不包含 Key 或完整推送 URL。
- 验收：WireMock 校验三项参数与中文标题正文、超时/业务错误/未配置、渠道组合与降级幂等；真实启动健康检查。真实 Bark 通知和点击唤起需设备及有效配置验证。

## 官方依据

- https://github.com/Finb/Bark/blob/master/docs/en-us/tutorial.md
- https://github.com/Finb/bark-server/blob/master/docs/API_V2.md

Bark 区分 `critical`（重要通知）与 `timeSensitive`（时效性通知）。此提案按用户“重要通知”使用 critical，不额外设置音量或持续响铃参数。

## 个人配置补充（2026-09-08 用户明确授权）

Bark 配置归属当前登录用户，用户端可修改，仅发送到被催办用户自己的设备 Key。新增个人配置表与 `/api/v1/me/bark` 读写接口，响应不返回密钥，空密钥保留旧值。服务端不可用全局设备 Key 替代个人目标。自动触发策略仍由后台维护。

## 系统异常配置补充（已批准）

后台保留独立系统 Bark 配置，仅供 Emby 同步失败、备份失败（含完整性和孤儿检查）使用，不发送个人催办。同一持续故障成功发送一次；恢复后重新布防，发送失败十分钟后允许重试。服务重启后内存去重状态重置。备份脚本写脱敏状态文件，服务端每分钟读取；数据库目录本身不可访问时脚本无法写状态，需要外部运维监控兜底。

2026-09-08：个人配置归属及空密钥保留、Bark HTTP 请求三项参数和中文标题正文、替代渠道失败不双发、系统故障合并及恢复后通知的窄测试通过；临时数据目录真实启动应用，V001 至 V006 迁移通过，健康检查 UP；46 个 App API 操作契约一致；备份脚本真实备份和完整性/外键检查通过，状态为 OK。真机 Bark 接收和 URL Scheme 唤起、GitHub CI 全量验证尚待执行。

## 发布前审查修复

个人配置保存和实际发送均按完整 HTTPS 源站校验，默认仅允许 `https://api.day.app`。部署者可通过 `BARK_ALLOWED_ORIGINS` 逗号分隔配置可信自建源站（含端口）；普通用户不能增加可信主机。发送不跟随重定向，防止设备 Key 转交其他主机。系统目的地由受保护的后台配置，不继承个人目的地。

个人 Bark 配置纳入用户删除预览、显式删除顺序和审计计数，先于账号行删除，避免密钥仅被隐式级联而不留删除计数。

## 2026-09-09 个人配置界面修正

个人配置沿用设置页分组卡片、弹层头部和间距。开关独立成卡并显示启用状态；服务地址与设备 Key 使用短标题，说明放在字段下方；默认三项通知方式使用只读标签。表单适配横屏与键盘，保留关闭和加载重试入口。仅修正个人设置样式，不变更推送协议。

## 后台系统配置样式修正（2026-09-09）

系统 Bark 卡片放在运行配置标题、状态提示及现有外部依赖卡片之后，功能开关之前。统一使用后台 wcard、winput、wcheck、wbtn 样式，显示启用与密钥配置状态、服务地址、设备 Key、现有请求超时及字段错误；窄屏字段改为单列。任意保存按钮仍提交本页全部配置，不改变系统与个人推送隔离。

## Web 个人催办渠道样式修正（2026-09-09）

Web 后台在线与进度页的个人手动催办：自动选择、Server 酱、客户端全屏、个人 Bark 四项统一放在投递渠道单选区；点击渠道只选择，不发送。标题与附加说明位于下方；操作区仅保留立即投递、取消。选择个人 Bark 时明确使用收件用户自己的配置，窄屏渠道换行、明细与表单改为单列。

## 系统测试通知（2026-09-09 用户要求）

后台系统 Bark 卡片增加“发送测试通知”。POST /admin/api/settings/test-bark 无请求配置，使用已保存的系统目的地、超时和默认通知参数，发送固定测试标题与正文。手动测试不依赖异常通知开关、不改变配置，也不参与异常去重。未配置或发送失败返回 ok=false 与脱敏提示；成功仅表示 Bark 接口接受，提示管理员检查设备。沿用管理员 Session 与 CSRF。输入未保存时需先保存；请求期间禁用重复点击。

## 手动 Bark 通知级别（2026-09-09 已按用户要求调整）

手动催办（后台 MANUAL 与督学 SUPERVISOR）实际通过个人 Bark 投递时，读取收件用户当前生效策略（用户覆盖优先）及其时区下的当前时间。免打扰时段内使用普通通知 level=active，时段外保留 critical；分组、点击链接、标题、正文不变。免打扰开始包含、结束不包含，支持跨午夜；起止相同表示不启用免打扰。自动催办的免打扰不投递规则、系统异常及系统测试通知不变。
