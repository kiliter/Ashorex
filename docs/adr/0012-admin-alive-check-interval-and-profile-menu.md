# ADR-0012：模拟考试预置独立入口与按视频进度百分比验活

- 状态：已接受
- 日期：2026-09-01

## 背景

模拟考试预置是用户编排今日作战单前需要直接维护的业务数据，隐藏在“学习偏好”页面会降低可发现性。原验活按真实观看分钟排期，无法稳定对应视频内容位置；倍速播放时，验活位置与可信进度校验也会出现偏差。

## 决策

“模拟考试预置”作为“我的”页面中的独立菜单项，与“学习偏好”并列；学习偏好页不再承载模拟考试入口。

所有用户使用同一套验活设置：可以关闭验活，也可以通过滑杆设置每推进视频可信进度 `1%～50%` 验活一次，默认 `50%`。滑杆值是相邻验活检查点之间的视频内容进度，不是墙钟时间；因此 `1.0x` 和 `2.0x` 会在相同视频位置触发。

服务端把百分比换算为绝对视频位置并持久化。创建观看会话时从当前可信最大位置排出下一检查点；验活确认后从最新可信最大位置继续排期。检查点达到视频完成阈值时不再创建新的验活。历史分钟等级和管理员固定秒数不再参与排期。

心跳增加 `playbackSpeed`。服务端只接受 App 支持的 `1.0x`、`1.25x`、`1.5x` 和 `2.0x`，允许的播放位置增量按倍速扩大，但有效学习时长仍按真实经过时间累计，不能通过倍速放大学习时长。

## 后果

- “我的”页面直接显示“模拟考试预置”和“学习偏好”两个菜单入口。
- `users` 增加非空的 `alive_check_interval_percent`，默认 `50`；旧秒数字段保留但停止读取，保持迁移追加性。
- `watch_sessions` 增加 `alive_check_due_position_ms`，旧观看时长阈值字段保留但停止读取。
- 偏好 API 改为 `aliveCheckEnabled` 和 `aliveCheckIntervalPercent`；所有角色拥有相同读写权限。
- 心跳最多每 10 秒上报一次，因此弹窗可能略晚于检查点，但不得跳过检查点。

## 被否决的方案

- 继续使用分钟等级：不同视频长度和倍速下无法对应稳定的内容检查点。
- 只修改 Flutter 的弹窗时间：验活由服务端驱动，本地规则会破坏服务端业务真相和重启恢复能力。
- 按倍速累计更多有效学习时长：倍速只改变内容推进速度，学习时长仍必须使用真实经过时间。
- 将模拟考试预置继续放在学习偏好页并增加快捷按钮：两个入口会造成导航重复，且没有解决信息架构混乱。
