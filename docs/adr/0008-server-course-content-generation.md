# ADR-0008：服务端恢复课程内容生产能力

- 状态：已接受
- 日期：2026-08-31
- 部分替代：ADR-0007
- 恢复并收缩：ADR-0006 的 ASR、LLM 运行时配置部分

## 背景（Context）

ADR-0007 将服务端 AI Runtime 完整删除，并将课程全文和 Markdown 摘要改为管理员在仓库外生成后批量导入。实际使用中，Emby 已能高效地从视频媒体项直接输出仅音频转码流；一个约 30 分钟课时可以在远短于播放时长的时间内取得完整 16 kHz 单声道 MP3。管理员希望在课程后台直接触发转写和摘要，减少课时内容生产的人工搬运，同时保留 ZIP 导入作为人工覆盖和故障兜底。

本次需求不恢复通用 AI 聊天、智能体、MCP、联网搜索、AI 计划或其他业务写能力。ASR 和 LLM 只为课时生成只读全文、摘要和不可直接发布的题目草稿。

## 决策（Decision）

服务端增加三类相互独立的持久化后台任务：

```text
TRANSCRIBE：Emby 音频流 → OpenAI-compatible ASR → 课时全文
SUMMARIZE：课时全文 → OpenAI-compatible LLM → Markdown 摘要
GENERATE_QUIZ：课时全文与摘要 → OpenAI-compatible LLM → 待审核题目草稿
```

转写通过 Emby `/Audio/{Id}/stream.mp3` 获取 16 kHz、单声道、64 kbps 音频，不下载完整视频，也不在上岸服务端运行 FFmpeg。服务端将音频流写入临时 MP3，再以 multipart 请求调用 `/v1/audio/transcriptions`。对 mlx-audio 使用 `stream=true`，逐行读取 NDJSON 响应的 `text` 并按顺序拼接，完整成功后一次性保存全文。

摘要和 AI 出题通过稳定版 LangChain4j 1.19.x 的 OpenAI-compatible ChatModel 调用 `/v1/chat/completions`。不使用仍为预发布版本的 Spring Boot 4 Starter。短全文直接处理；长全文使用共用的上下文预算和递归分层处理器，先分段提炼，再分组归并，直到输入落入模型窗口。LLM 只接收当前课时全文、摘要和题目生成约束，不读取计划、欠债、用户学习记录或其他业务数据。

AI 生成的题目只能进入独立草稿，不直接写入正式 `questions`。管理员可以逐课时审核编辑，也可以在课程范围选择已校验草稿后批量发布。批量发布先完成全部草稿校验，再在一个事务中写入正式题目；任意草稿不合法时整批不发布。发布只追加新题，不删除或覆盖已有正式题目，同一草稿重复提交必须幂等。

模型目录从固定的 OpenRouter Models API 读取并缓存到 SQLite。缓存保存模型 ID、显示名、上下文长度、最大输出 Tokens、Tokenizer、支持参数和抓取时间。OpenRouter 只提供模型元数据；实际摘要 Base URL 仍可配置为 CPA 或其他 OpenAI-compatible 上游。模型不在目录中时允许手动配置。

课时级提供“一键转文本”“AI 摘要”和“AI 出题”，课程级提供三个对应批量操作。所有任务使用一个全局串行 Worker，按队列顺序逐个执行。已有内容默认跳过，重新生成必须显式触发。失败任务不自动重复消费，可由管理员手动重试。

定时补全任务实现但默认关闭。启用后仅扫描缺失全文或摘要的课时，不自动覆盖已有内容，仍进入同一全局串行队列。

ZIP 导入继续保留。ZIP 成功导入时同时覆盖对应课时的全文和摘要。

## 后果（Consequences）

- 管理员可以在课程后台完成转写与摘要，不需要手工下载视频或在仓库外拼装内容。
- 服务端重新持有 ASR、LLM 和 OpenRouter API Key，数据库文件和备份权限需要继续保护。
- 任务、阶段日志和耗时落入 SQLite；临时音频只存在于任务执行期间，成功或失败后都删除。
- 服务端仍不提供 AI 聊天、MCP、智能体或 AI 业务写入口，Flutter 继续只读查询课时内容。
- AI 题目只有经过管理员明确发布后才进入正式题库；生成草稿不会影响学习端。
- OpenRouter 目录缓存失败时继续使用旧缓存或手动模型配置，不阻断已配置模型的摘要或出题任务。
- `lesson_study_contents` 需要允许全文和摘要独立存在；读取 API 需要表达部分就绪状态。

## 被否决的方案（Rejected Alternatives）

- Controller 内同步完成转写和摘要：长任务容易导致浏览器和反向代理超时，且无法可靠查看状态和重试。
- 使用内存队列：服务重启会丢任务和执行状态。
- 下载完整视频后在本地 FFmpeg 提取音频：Emby 已能直接输出音频，会增加不必要的网络、磁盘和进程管理成本。
- 恢复通用 AI Chat、MCP 或智能体：超出当前“课程内容生产”的明确范围。
- 将 OpenRouter 固定为实际推理上游：用户的实际上游可以是 CPA，模型目录与推理地址必须解耦。
