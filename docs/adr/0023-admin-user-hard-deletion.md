# ADR-0023：管理后台物理删除用户及其全部关联记录

- 状态：已接受
- 日期：2026-09-04

## 背景

管理后台此前只能创建、启用和禁用用户，没有删除入口。测试账号和不再使用的账号会长期留在系统中，其学习数据也无法清除。

直接对数据库执行 `DELETE FROM users` 并不可行。实测结论如下：

- `users` 被 15 张用户数据表以 `ON DELETE CASCADE` 引用，覆盖完整，没有遗漏含 `user_id` 的表。
- 但 `debt_repayments` 没有 `user_id` 列，却以 `ON DELETE RESTRICT` 同时引用 `daily_plan_items` 和 `learning_debts`。这两张表会被级联删除，于是 RESTRICT 直接阻断整个语句。在数据库副本上构造带还债记录的用户后，`DELETE FROM users` 返回 `FOREIGN KEY constraint failed`。
- 模拟考试试卷照片保存在 `MOCK_EXAM_ATTACHMENTS_DIR` 磁盘目录中，`mock_exam_attachments` 行被级联删除后，文件会变成无法追溯的孤立文件。

## 决策

新增管理后台删除用户能力，删除是不可恢复的物理删除。

删除范围与顺序：

- 先显式删除该用户的 `debt_repayments`，匹配条件是欠债属于该用户，或还债关联的计划项目属于该用户的作战单。
- 再删除 `users` 行，由 15 处 `ON DELETE CASCADE` 清除其余用户数据。
- 外键保留为安全网：漏删任何被 RESTRICT 引用的表都会让事务失败，而不是静默留下孤儿数据。因此本方案不移除任何外键约束。

安全约束：

- 管理员账号不可删除，返回稳定错误码 `USER_DELETE_ADMIN_FORBIDDEN`，避免后台失去唯一入口。
- 必须手工输入与目标用户完全一致的用户名才会执行，不匹配返回 `USER_DELETE_CONFIRMATION_MISMATCH`；页面另有一次浏览器确认。
- 用户不存在返回 `USER_NOT_FOUND`。
- 删除操作记录 WARN 日志，包含用户 ID 和附件数量，不记录用户名、显示名或文件路径。

附件清理：

- 附件磁盘路径必须在数据库删除之前读取，否则级联删除后无法再定位文件。
- 文件清理在事务提交成功后执行，清理器只允许删除模拟考试附件根目录内的文件，拒绝越界路径。
- 清理失败只记录 ERROR 日志，不回滚已完成的数据库删除。

## 后果

- 管理员可以彻底清除测试账号和废弃账号，数据库与磁盘不再残留该用户数据。
- 删除后该用户的 Refresh Token 随级联清除，但已签发的 Access Token 在有效期内仍能通过 JWT 校验，窗口期最长 15 分钟。窗口期内的写操作会因外键约束失败，不会产生指向已删用户的孤儿数据。
- `debt_repayments` 的显式删除成为删除链路的必要步骤，后续若新增没有 `user_id` 又以 RESTRICT 引用用户数据的表，必须同步扩展该顺序。
- 删除用户不影响课程、课时、题库、全文摘要和内容任务等共享数据。

## 被否决的方案

- 移除全部外键约束以便直接删除：会让 28 处依赖 CASCADE 的清理静默失效、27 处 RESTRICT 保护网消失，并使 `PRAGMA foreign_key_check` 永久失去意义；SQLite 还需重建 33 张表，代价与风险都远高于收益。
- 只做逻辑删除或仅禁用账号：无法满足清除学习数据的需求，数据仍然留存。
- 依赖 `DELETE FROM users` 的级联顺序碰巧成功：实测已证明存在还债记录时必然失败，不能作为实现依据。
- 删除时保留匿名化的学习记录：这些记录全部以 `user_id` 为归属键，匿名化会破坏可信学习数据的归属语义，也无人会再使用。
