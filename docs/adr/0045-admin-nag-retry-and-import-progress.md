# ADR-0045：后台失败催办闭环与课程导入布局

- 状态：已接受（2026-09-09 用户确认）
- 日期：2026-09-09
- 关联：T13 / T18 / T19，原型 8-4 / 8-5 / 8-6

## 冻结规则冲突

Spec §6.3 仅定义 PENDING、DELIVERED、RESPONDED、EXPIRED，没有管理员取消终态与失败重投。ADR-0037 将选择与结果放在同一导入弹窗，现改为独立进度与结果弹窗。以下增补已获用户批准。

## 决策

1. 仅对仍为 PENDING、已有投递尝试且全部失败的催办提供「取消投递」「重新投递」。已投递、已回应、已过期、已取消的记录拒绝操作。
2. 取消需二次确认，进入新增 CANCELLED 终态，保留催办与失败流水、管理员操作时间及身份；从待投递与待回应查询排除，不再触发降级或重试。取消不撤回外部通知。
3. 重新投递复用原催办 ID、标题和正文，按当前有效策略与在线状态选择渠道，追加投递尝试，保留旧失败记录；成功进入 DELIVERED，失败仍可取消或重试。不新建催办、不重复计算每日次数；终态与并发重复请求必须由服务端拒绝或幂等处理。外部请求不得占用长写事务。
4. Web 课程库表格使用受视口约束的固定高度容器，表体内部滚动、表头固定，搜索与分页留在滚动区外；数据增加不撑长页面。
5. Emby 候选表格同样固定高度、表头固定，搜索、多选、分页与导入按钮保持可见；全选仍覆盖筛选结果中所有未导入课程，排除已导入与归档。
6. 点击导入所选立即打开独立进度弹窗：顶部圆形进度环显示已处理数 / 总数和百分比，显示当前课程；未知等待只显示加载状态，不伪造百分比。下方固定高度日志区域逐项显示成功、已存在或失败原因，不混入候选表格页面。
7. 逐门串行处理，单项失败继续；导入期间禁止重复提交及关闭进度弹窗，结束后保留结果、提供关闭和重试失败项。重试按本轮实际数量重新计算进度。

## 实施与验收

- T13 / T18：补充终态、后台取消/重投接口、操作留痕及中文展示；追加数据库迁移，不修改已发布 baseline；同步涉及的 API 契约及状态消费者。
- T19：修复两个表格的滚动容器，拆出导入进度与结果弹窗，同步唯一 UI 原型。
- 窄验证：全部失败操作资格、终态拒绝、重投追加流水、取消后不再下发、并发互斥、失败重试；两个表格大量数据时高度不变，进度计数与逐项结果一致。
- 数据库迁移或 Bean 变更后执行真实启动并检查健康端点 UP；本地仅运行相关窄测试及后台构建，全量验证交 GitHub CI。

## 接口与存储

- POST `/admin/api/nags/{id}/cancel`、`/retry`：请求 `{latestAttemptId}`，成功返回 204；最后一次尝试 ID 来自列表 `deliveryAttempts[].id`，过期版本返回 `NAG_STATE_CHANGED`，在途重复操作返回 `NAG_OPERATION_IN_PROGRESS`。
- 仅管理员 Session + CSRF 可调用，操作人只取认证身份。重投使用当前策略；自动催办免打扰时拒绝重投，全部渠道关闭时先提示启用。旧日期不重投，取消仍允许对尚未由扫描器过期的全失败项闭环。
- GET `/admin/api/nags` 新增 `adminActions`，包含催办 ID、CANCEL / RETRY、管理员及时间。追加 V008，原子保留父子表并扩展 CANCELLED；操作历史存入 `nags.admin_actions` JSON 数组，随原记录级联，不新增孤儿表。
- App 催办历史状态新增 CANCELLED，拒绝回应返回 `NAG_CANCELLED`；已投递/已取消状态均不能被迟到投递结果回退。
- 重投的串行互斥只在内存中持有，不在外发时占用 SQLite 写事务；服务重启不承诺外部推送恰好一次。
