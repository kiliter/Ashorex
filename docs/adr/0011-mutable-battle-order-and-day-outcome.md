# ADR-0011：使用可整体保存的今日作战单并自动判定日终结果

- 状态：已接受
- 日期：2026-09-01

## 背景

原每日计划要求用户先编辑再锁定，锁定后完全不可修改，并提供会立即生成欠债的手动“开摆”。实际使用需要在统一编排区内先组织课时和模拟考试，保存后仍能通过“修改作战单”整体调整；专注计时也应是首页独立工具，而不是计划任务。继续沿用不可变锁定模型会让课程加入、临时调整和日终统计相互冲突。

## 决策

首次保存作战单编排区后创建 `ACTIVE` 今日作战单，之后可使用版本号和完整项目快照原子替换。未开始项目可以删除，删除后不再产生欠债；正在执行、等待上传材料或已完成项目不可删除或更改。服务端保存每次作战单修订用于审计，不限制每日修改次数。

已学课时加入后成为“复习快捷入口”：只跳转到可自由回看的播放器，第一次有效播放心跳记录复习事件，但不参与进度、完成率、欠债或日终结算。专注计时移到首页右滑小工具菜单，保留独立学习记录。

移除客户端手动“开摆”。服务端按用户时区幂等结算自然日：有作战单时按未完成承诺结算；没有有效作战单但存在可信观看、模拟考试或专注记录时记为“自由学习”；两者都没有时记为“开摆日”。“开摆日”不产生欠债。

模拟考试由用户维护的考试预置生成，保存进作战单时复制名称和时长快照；截止或提前交卷后至少上传一张试卷照片才完成。附件与数据库元数据一起纳入备份恢复。

模拟考试按复习任务处理：执行记录可用于日报、周报审计，但不纳入课程进度，也不在日终生成学习欠债。

## 后果

- `LOCKED` 迁移为 `ACTIVE`，作战单不再因为当前项目全部完成而提前关闭，只在日终进入终态。
- 作战单写接口改为带版本号的完整快照保存，课程详情不再直接增加计划项目。
- 报表需要区分“作战完成、作战未完成、自由学习、开摆日”，并可列出复习审计事件。
- 旧 `ABANDONED` 和旧专注计划数据继续只读兼容，但不再产生新的手动开摆或专注计划项目。

## 被否决的方案

- 锁定后每天只允许修改三次：次数规则不能解决批量编辑和原子保存问题，还会增加失败重试时的计数争议。
- 允许直接从课程详情加入计划：会绕过统一编排确认，并让多个入口的修改规则不一致。
- 把复习当成新的可信观看任务：会重复引入进度、完成阈值和欠债计算，偏离快捷入口目的。
