# ADR-0006：允许管理员配置运行时外部服务

- 状态：提议
- 日期：2026-08-30

## 背景（Context）

V1 原设计要求 Emby、LLM、ASR 和 MCP 配置只来自服务端环境变量。这一方式安全且部署模型简单，但在本地开发和少于 5 人使用的自建环境中，每次修改配置都需要重启服务，降低了管理效率。管理员需要通过现有内部 Web 后台修改这些服务配置，并让新调用立即生效。

## 决策（Decision）

在仅 ADMIN Session 可访问的 Thymeleaf 后台增加统一服务配置页。环境变量继续提供首次启动的初始配置；管理员第一次保存后，SQLite 单行配置成为完整运行时来源。配置保存成功后原子刷新内存快照，新发起的外部调用立即使用新值。

配置包括 Emby、LLM、ASR 和 MCP。API Key 与 Token 在管理员页面中使用可显示/隐藏的密码框。为保持实现简单，SQLite 中的外部密钥不额外加密，且随数据库一起备份。配置页面使用 CSRF、禁止缓存，并且密钥不得进入 Flutter、业务 API、日志或错误响应。

共享配置读取接口位于 `common.integration`。管理后台负责编辑，AI 和 Emby 只依赖该公共应用接口，不依赖管理页面或 Controller。

## 后果（Consequences）

- 管理员不再需要为了修改外部服务配置重启应用。
- 环境变量部署方式保持兼容，但数据库存在配置后不再逐字段回退环境变量。
- SQLite 数据库和备份包含可读取的外部密钥，数据库文件权限与备份保护因此更加重要。
- 外部服务适配器必须按调用取得不可变配置快照，不能在 Bean 初始化时永久捕获配置。
- 修改 Emby 配置可能影响正在进行的 HLS 分片请求，管理员应尽量在无人播放时修改。

## 被否决的方案（Rejected Alternatives）

- 继续只使用环境变量：不能满足保存后立即生效的管理体验。
- 引入独立配置中心：超出单机、少用户 V1 的复杂度需求。
- 使用额外主密钥加密 SQLite 字段：需要密钥轮换和恢复流程，当前用户明确选择轻量方案。
- 保存配置历史和提供回滚：当前没有审计或多管理员协作需求。
