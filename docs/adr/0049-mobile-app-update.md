# ADR-0049：移动端主动检查与下载安装

- 状态：已接受，2026-09-10 用户确认按此逻辑实施。
- 对应：R49 / T49；补齐 ADR-0048 明确未实现的移动升级范围。

## 决策

App、Spring Boot、后台与 GitHub Release 使用同一个三段版本号。仅比较版本号，按数字分段比较；构建号只作平台内部打包字段，不参与更新判断、不展示。同版本不得替换安装包，CI 发布前检查版本一致，附件上传不使用 clobber。

学习端、督学端「我的」增加「检查更新」及当前版本，进入「版本与更新」页后用户明确点击按钮才查询。启动、登录、前台恢复、进入页面及心跳均不请求升级接口。无后台轮询、强制升级或自动下载。当前版本大于等于发布版本显示无需更新；查询失败及旧服务端不支持独立提示。

Spring Boot 查询固定 kiliter/Ashorex 的最新非草稿正式 Release，成功元数据缓存五分钟并合并并发请求。安装包从匹配的版本、平台文件名及 GitHub SHA-256 元数据确认就绪；缺少附件或摘要时不提供下载。使用 GitHub 原生 Release 元数据，不新增重复版本清单。

GET /api/v1/app-updates/latest?platform=android|ios 返回直接 DTO。GET /api/v1/app-updates/releases/{tag}/assets/{platform} 为公开流式代理，校验 tag、平台、HTTPS 源站与每跳重定向，固定四个下载并发；设置连接和读取超时，支持单 Range、If-Range、200/206/416，关闭中断的上游连接，不转发登录凭据或上游错误正文。这里只读公开发布物，匿名访问不放宽业务 API。

Android 显示进度并允许取消、失败后续传；临时文件按摘要隔离，上游忽略 Range 时重写文件，完整性校验后才允许安装。通过仅暴露更新缓存的 FileProvider 调起系统安装；Android 8+ 引导授予安装未知来源应用权限，返回后继续已下载的安装。原生端再次检查摘要、包名、版本与签名，系统用户确认是必要步骤，不伪报安装成功。

iOS 在用户点击后通过系统浏览器打开 /downloads/app/{tag}/ios，页面提供同源 IPA 下载和轻松签自行签名安装说明。无自动签名、无自动安装、不处理用户证书；不同签名方式的覆盖安装与数据保留不能由 App 保证。模拟器隐藏真机安装动作。

## 兼容和发布

增量接口，不修改旧 App 业务契约；新 App 连接旧服务端仅升级页提示不支持。先部署新服务端，再发布带入口的 App；已发布旧 App 首次必须手动更新。Android 构建号继续由 CI 维护以避免倒退，与用户看到的版本判断无关。

## 验收边界

服务端窄测试覆盖平台及源站校验、缺附件、Range、错误正文隔离；Flutter 覆盖点击触发、无隐式检查、数字版本比较、200/206 续传及摘要失败。真实服务启动确认 UP，验证实际接口；iOS 模拟器构建及 Android 构建验证原生桥。物理设备上的安装权限、覆盖安装、签名兼容与 iOS 自行签名流程须独立验收，不能以模拟器测试替代。

入口位置：我的页面底部「应用信息」卡片，位于退出登录上方，复用现有设置行与右侧版本号。
