# 移动端升级实施计划（已确认）

依据 [ADR-0049](../adr/0049-mobile-app-update.md)，用户已批准在当前 main 实施，不另建工作树；保留此前后台高度修复。

1. 统一三段版本号，按数字分段比较，构建号不参与查询和判断。CI 校验 App、服务端、后台、tag 版本一致，同版本附件不覆盖。
2. Spring Boot 查询固定 GitHub 最新正式 Release，返回版本、说明、大小、摘要和固定同源路径。成功结果缓存五分钟，附件不完整明确提示。使用现有 GitHub 资产元数据，不增加移动版本清单。
3. 流式中转 APK / IPA，支持单 Range、超时、客户端断开和并发限制；iOS 下载说明页匿名可用，下载链接不携带凭据。
4. 两个角色共享「我的 → 应用信息 → 检查更新」，显示当前版本；仅页面上的检查按钮发起查询，生命周期与心跳不触发。
5. Android：用户点击下载、进度、取消、断点续传、校验、安装权限引导及系统确认安装。iOS：打开下载页，用户下载后自行签名。
6. 窄测试、原生构建、真实 ApplicationContext 启动与 API 验证；CI 全量验证及物理设备覆盖安装单独报告。

交付不包含强制升级、自动查询、自动下载、静默安装、iOS 自动签名。先升级服务端，再安装具备入口的 App；旧 App 首次手动更新。

入口位置：我的页面底部「应用信息」卡片，位于退出登录上方，复用现有设置行与右侧版本号。
